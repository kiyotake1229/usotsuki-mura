# ドキュメント管理・コミット規則

## 開発完了後の自動ドキュメント作成（重要）

**コード変更を伴う開発タスクを完了したら、ユーザーの指示を待たずに自動的にドキュメント作成を開始すること。**

### 判定フロー

1. 開発タスク（コード変更）が完了した
2. 変更種類を判定する:
   - NEW / BUG / ENH / SEC → **必ずドキュメントを作成**（ユーザーに確認不要）
   - FIX → 推奨（簡潔でよい）
   - タイポ修正・コメントのみ → スキップ（`[no-doc]` でコミット）
3. ドキュメント作成 → `generate_docs_json.sh` 実行
4. 完了をユーザーに報告

### 自動作成の手順

1. `docs/manager/docs.json` の `next_no` を確認して連番を取得
2. 命名規則に従いファイル作成: `YYYYMMDD_種類_連番_場所_内容.md`
3. `docs/README.md` の必須記載項目に従い内容を記述
4. `docs/manager/generate_docs_json.sh` を実行

## ドキュメント管理

docsフォルダにドキュメントを追加・修正する際は、必ず先に `docs/README.md` のルールを確認すること。

- 命名規則: `YYYYMMDD_種類_連番_場所_内容.md`
- 場所: ALL（全体）/ APP（画面）/ ENG（推論エンジン・問題生成。`index.html` 内）/ PWA / IOS
- 次の連番: `docs/manager/docs.json` の `next_no` を参照
- アプリ全体の現状は `docs/20261008_DOC_0001_ALL_現状の仕様と構成.md`。最初にこれを読む

### docs.json の更新（重要）

**`docs/*.md` ファイルを作成・編集した後は、必ず以下のコマンドを実行すること:**

```bash
bash docs/manager/generate_docs_json.sh
```

## このアプリでの注意

- 推論エンジン（ENG）を変えたら、文書を書く前に `node tools/check-engine.mjs index.html` を実行し、PASS を確かめる。結果（PASS/FAIL・生成時間）を文書の「確認」に書く
- 問題の作り方が変わる変更（生成の手順・表・定数・言い回しの選び方など）は、全員の日替わり問題を変える。エンジンの `VERSION` を上げ、そのことを文書に必ず書く
- 開発中のエンジンを別ファイルで作るときは、仕上がったら `index.html` の `// ==ENGINE START==`〜`// ==ENGINE END==` の間に入れ直す（アプリは1ファイルで完結させる）
- 作業用・実験用のファイルはこのフォルダに残さない（Dropbox で共有されている）

## gitコミット時のドキュメント管理

2026-10-08 時点ではこのフォルダは git 管理していない。GitHub Pages で公開するときに git を始め、以後は下のルールに従う。それまでは「ドキュメント作成 → `generate_docs_json.sh` 実行」までを行う。

### コミット前チェックリスト

| 変更種類 | ドキュメント | 必須度 |
|----------|-------------|--------|
| 新機能追加 (NEW) | 必須 | ◎ |
| バグ修正 (BUG) | 必須 | ◎ |
| 機能改善 (ENH) | 必須 | ◎ |
| セキュリティ対応 (SEC) | 必須 | ◎ |
| 軽微な修正 (FIX) | 推奨 | ○ |
| リファクタリング (REF) | 状況による | △ |

### コミットメッセージ規則

```
[#連番] 変更内容の要約

- 変更ファイル一覧
- 関連ドキュメント: docs/YYYYMMDD_TYPE_NNNN_CAT_タイトル.md
```

ドキュメント不要の場合:
```
[no-doc] タイポ修正: path/to/file
```

### コミット手順

1. 機能実装・修正を完了
2. ドキュメントを作成（`docs/README.md` のルールに従う）
3. `docs/manager/generate_docs_json.sh` を実行
4. `git add` でソースコードとドキュメントを含める
5. コミットメッセージに `[#連番]` を付けてコミット

### ドキュメント不要の例外ケース

- タイポ修正
- コメントの追加・修正のみ
- コードフォーマットの調整のみ
- 開発環境のみに影響する変更
