# 今週の難問（月曜ごとに全員共通の9人の事件）

- 管理番号: #0018
- 種類: NEW（新規開発）
- 対象: アプリ本体（APP）
- 作成日: 2026-10-14
- 関連: #0017（はじめての事件）・#0019（事件簿の全日表示）と同じコミット、#0003（9人の難問）、#0004（難問の画面・Web Worker）、#0010（日付の決まり `DAYRULES`）

## 概要

月曜ごとに、容疑者9人・★3 の事件が1つ届く「今週の難問」を足した。同じ週なら全員・全端末で同じ問題になる。毎日の連続日数・解決数・ノーミス数には数えず、解いた週の数を記録する。推論エンジンは変えていない（seed に文字列を渡すだけ）ので、日替わり・練習・難問の問題は1つも変わらない（`VERSION` は 3 のまま）。

## 対象ファイル

- `index.html`（画面の HTML・CSS・JavaScript。日付の決まり `// ==DAYRULES START==`〜`END` に週の関数、保存 `// ==STORE START==`〜`END` に `weekly`）
- `tools/check-app.mjs`（週の決まり・156週の回帰ハッシュ・保存の検査を追加）
- `support.html`（遊び方に「今週の難問」、よくある質問「『今週の難問』と練習の『難問』は何が違いますか」、1回の目安、プライバシーポリシーの保存する情報）
- `ios-app/岩崎さんへの引き渡し手順.md`（申請の説明文・プロモーション用テキスト・審査用の遊び方）

## 変更内容

### 1. 週の決まり（`DAYRULES` に追加）

| 関数・定数 | すること |
|---|---|
| `FIRST_WEEK` = `'2026-09-28'` | 第1週の月曜（No.1 の 2026-10-01 を含む週） |
| `mondayOf(日付)` | その日を含む週の月曜。曜日は日付の文字列から UTC で求める（端末の時差・夏時間に左右されない） |
| `weekNoOf(日付)` | 第N週。No.1 より前の日付は No.1 の日に丸めてから数える（＝第1週） |
| `weekMonday(N)` | 第N週の月曜 |
| `weekSeed(月曜)` | `'usotsuki-week-' + 月曜の日付（ハイフンなし）`。今週（第3週）は `usotsuki-week-20261012` |
| `weekRange(月曜)` | 「10/12〜10/18」 |
| `isThisWeek`・`weekName` | 今週なら「今週の難問」、終わった週は「週の難問」 |

- 問題は `Engine.generate({ seed: weekSeed(月曜), people: 9, star: 3 })`。練習の難問と同じく Web Worker で作り、Worker が使えない環境ではメインスレッドで作る（進み具合の帯も同じ）
- 保存を読む `sanitize` でも週の関数を使うので、`DAYRULES` を保存の処理より前に移した

### 2. ホームのカード

- 今日の事件の下に「第3週 10/12〜10/18 ★★★」のカード。札「全員共通・月曜に入れ替わり」、状態（未解決「仮定を重ねて、じっくり」／捜査の途中・時間・ミス／解決の判子・□■・時間）
- 題名は一度開いた週だけ出す（作るまで題名が分からない。ホームを開くたびに9人の事件を作ると重くなるため）。まだのときは「容疑者9人の大事件」
- 練習の「難問」の説明を「毎回ちがう9人の事件。何度でも遊べます」にし、遊び方にも「（今週の難問とは別）」と書いた

### 3. 事件の画面・結果・共有

- 上部の見出し: 今週は「今週の難問 第3週」、終わった週は「週の難問 第1週 9/28〜10/4」（共有を見た人に今週の問題と思わせないため）
- 盤面の見出し: 「第3週（10/12〜10/18）」
- 結果: 「今週の難問を解いた週 N週」。判子の周りの文字「嘘つき村 駐在所 ・ 今週の難問 第3週 ・ 容疑者9人 ・」
- 共有画像の名前は `usotsuki-week3.png`。共有画像の事件の行は「今週の難問 第3週　10月12日〜10月18日」（終わった週は「週の難問 第1週　9月28日〜10月4日」）、コピーの文の1行目は「嘘つき村の事件簿 今週の難問 第3週（★★★・9人）」（終わった週は「週の難問 第1週 9/28〜10/4」）。答えと村人の名前は描かない（今までどおり）
- ［次の事件］は出さない（`nextCase` を通す。前は今週の難問・はじめての事件で★1の練習が開いていた）
- 毎日の連続日数・解決数・ノーミス数・練習の解決数には数えない。事件簿の合計の下に「今週の難問を解いた週 N週」

### 4. 保存（`usotsuki.v1`。形の v は 1 のまま）

- `weekly: { 'YYYY-MM-DD'（その週の月曜）: { state: 'playing'|'solved', 判子・ミス・ヒント・提出・時間…, title, v } }`
- 開いた週の月曜の記録に書く（月曜0時をまたいで解いても、開いた週の記録のまま）。解決済みは上書きしない
- 読み込み（`sanitize`）: キーは**実在する月曜の日付**だけ残す（`2026-10-32`・`2026-13-01`・`2026-02-30`・月曜でない日などは、その1件だけ捨てる）
- 古い版のタブが `weekly` の無い保存を書いた場合は、記録を消した回（`epoch`）が同じなら戻す（`carryNew`）。別のタブとの重ね合わせで、同じ週は解決を優先する
- 「記録を消す」で一緒に消える

### 5. 新しい関数

`renderWeekCard`・`weekStatusHTML`・`weeksSolved`・`weekRangeLong`（共有画像の「10月12日〜10月18日」）。共通の `nextCase`・`topLabelOf`・`carryNew` は #0017 と同じ。

### 確認で見つかって直したこと（2026-10-14）

| 指摘 | 内容 | 直し |
|---|---|---|
| 壊れた日付で記録が全部消える（major） | 保存の `weekly` に実在しない日付のキー（`2026-10-32` など）があると、読み込みが失敗して解決数・連続を含む記録が全部既定に戻っていた | 実在する日付かを先に確かめ、1件ずつ読む。読めない1件だけ捨てる |
