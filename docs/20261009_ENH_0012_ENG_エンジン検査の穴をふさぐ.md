## 概要

点検で、`tools/check-engine.mjs` が「エンジンが壊れても PASS してしまう」穴を9つ見つけた（指摘 #25〜#33）。今のエンジンには誤りが無いことは別の監査で確かめてあり、利用者への害は無い。ただ、決まりでは「エンジンを変えたら check-engine の PASS を確かめる」ので、この関門をすり抜ける誤りがそのまま公開されうる。検査を足して、わざと壊したエンジンで FAIL になることを確かめた。

**変えたのは検査だけ。エンジン（`index.html` の ENGINE START〜END）は変えていないので、問題は変わらず `VERSION` は 3 のまま。** 検査は 64項目 → **82項目**、時間は約17秒（引数なし）。

## わざと壊したエンジンで FAIL になるか

点検のときに作った「壊した写し」に新しい検査をかけた（引数 `--count 15 --days 20 --count-hard 6`）。どれも新しい項目が FAIL した（直す前の検査では、回帰ハッシュ以外は PASS していた）。

| 壊し方 | FAIL した新しい項目 |
|---|---|
| 「→」の後の正直者と嘘つきを入れ替え／矛盾の文の本当とウソを入れ替え／仮定の結論が仮定と同じ／区分A の書き出しを反対／支えの文の人を入れ替え | 解説の文が中身と合う |
| 仮定の外で HONESTCOUNT の直接の手を見落とす（3〜9人、7人以上だけ、の2通り） | 仮定の前に直接の手が残っていない |
| 答えの決まる DIFF/SAME を区分C にする | 区分が条件に合う・文が中身と合う・stats |
| stats.back を +7、unused を [] にする | stats.back・stats.unused が解説と同じ |
| check の本当/ウソを逆・正直者/嘘つきを逆・理由を逆向き・引用を隣の証言 | check: 食い違いの文が中身と合う |
| hint の犯人の見直しを消す・見直しの対象を別の人にずらす | hint: 「見直し」「そろった」の判定が正しい |
| 3〜9月だけ季節の条件を無視 | 事件の割り当て: 季節に合う事件 |
| 9人の表（climb）を 80→81 | 回帰: 7〜9人（難問）90問 |
| WORKER_TAIL の `E.generate` を `E.make` に／ready の通知を `readyy` に | Worker: アプリと同じ経路… |

## 確認

- `node tools/check-engine.mjs index.html`: **PASS（82項目・16.5秒）**。回帰ハッシュ3つ（日替わり365日・練習240問・難問90問）も PASS。`VERSION` は 3 のまま
- 生成時間の参考（2026-10-09、Mac・負荷 2〜3）: ★2 5人 アプリ形式 seed 400問 最大46ms、★2 6人 最大137ms、日替わり365日 最大107ms（2027-05-21・6人・★2）、開いた直後の日替わり 最大12ms、`dailyConfig('2036-10-01')` の初回 45ms。点検のときは負荷が高く（6〜10）、★2 6人の最悪 seed で約400ms、2036年の dailyConfig の初回で138ms が出ている
- 生成を速くする直し（★2・6人が重い問題、遠い日付の dailyConfig が遅い問題）は、問題の作り方が変わる（全員の日替わり問題が変わる）ので今回はしていない。直したら目安を合否に入れる
