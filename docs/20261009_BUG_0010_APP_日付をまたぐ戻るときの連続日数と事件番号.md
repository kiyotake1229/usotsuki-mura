# 日付をまたぐ・戻るときの連続日数と事件番号

- 管理番号: #0010
- 種類: BUG（バグ修正）
- 対象: アプリ本体（APP）
- 作成日: 2026-10-09
- 関連: #0001（6章「連続日数」に追記）、#0016（点検の報告。指摘 #12・#13・#14）

## 概要

日付と連続日数のまわりで、次の3つの不具合を直した。問題の作り方（エンジン）には触れていないので、日替わり問題・`VERSION`・回帰ハッシュは変わらない。

1. **夜に開いた「今日の事件」を0時を過ぎてから解くと、連続日数が消える**（指摘 #12・重さ major）。前日まで連続4日の人が、23:59 に開いて 0:00 過ぎに提出すると「当日以外に解いた事件は、連続日数に数えません」になり、翌日のホームは「連続 0 日」になっていた。★3（土日）は5〜10分かかるので、夜遅くに始める人には普通に起こる
2. **端末の日付が最後に解いた日より前に戻ると、連続が0と表示され、解くと連続が1に戻る**（#13・minor）。西へ移動したとき・手で時計を戻したときに起こる
3. **端末の時計が 2026-10-01（No.1）より前だと「No.-5」と出て、事件簿の一覧が空になる**（#14・minor）

同じ日のうちに、直したあとの確認で見つかった漏れも直した（下の「直したあとの確認で直したこと」）。この文書は、その分も入れた最終の姿を書いている。

## 対象ファイル

- `index.html`（画面の JavaScript と CSS）
- `support.html`（よくある質問・遊び方の連続日数の説明）
- `tools/check-app.mjs`（新規。画面の日付と連続日数の決まりの検査）

## 変更内容

### 1. 日付と連続日数の決まりを、試せる形の関数にまとめた

`// ==DAYRULES START==`〜`// ==DAYRULES END==` の間に、Engine と引数だけを使う関数を置いた（画面の状態 `S`・`P` には触れない）。`tools/check-app.mjs` がここを取り出して検査する。

| 関数・定数 | すること |
|---|---|
| `clampDay(d)` | 端末の日付が No.1（`FIRST_DAY` = 2026-10-01）より前なら No.1 の日にする |
| `clockBehind(丸める前の日付)` | 端末の日付が No.1 より前か（案内を出すため） |
| `TZ_SLACK` = 2 | 日付が戻っても連続を巻き戻さない幅（日）。時差でずれる日付は最大2日（UTC+14 と UTC-12 の差は26時間） |
| `openedOnDayOf(事件の日付, 今日, 記録)` | その日のうちに開いた事件か。今日の事件を開いたとき、または記録に `openedOnDay: true` が残っているとき |
| `countsOnDay(事件の日付, その日に開いたか, 今日, 時)` | その日の分として数えるか。当日に解いたとき、または**その日のうちに開いた事件を翌朝3時までに解いたとき** |
| `pendingDay(日替わりの記録, 今日, 時)` | 0〜3時に、前の日に開いた事件がまだ解けていなければ、その日付（ホームの案内と連続の表示に使う） |
| `addStreak(stats, 事件の日付)` | 連続日数を更新する。基準は「今日」ではなく**事件の日付**。最後に解いた日が事件の日付から2日以内の先なら、連続も最後に解いた日も**巻き戻さない**。それより先なら時計のずれとみなし、ふつうに数え直す（1日目から。最高は残る） |
| `shownStreak(stats, 今日, まだ間に合う)` | 表示する連続日数。最後に解いた日が今日か昨日なら続いている。最後に解いた日が今日より後でも2日以内ならそのまま見せる（3日以上先なら0）。0〜3時に前の日の事件がまだ間に合うときは、最後に解いた日が一昨日でも切れていない |

`today()` は `clampDay(Engine.localDateStr(new Date()))`、`streakNow()` は `shownStreak(S.stats, today(), !!pendingNow())` になった。

### 2. 0時をまたいで解いたとき（#12）

- 日替わりを開いたとき、`P.openedOnDay`（その日のうちに開いたか）を `openedOnDayOf` で決める。開いた日には、日替わりの記録に **`openedOnDay: true`** を残す（`saveProgress`。いちど付いたら外さない。`sanitize` もこの項目を残す）。そのため、ホームに戻ってから開き直したとき・読み込み直したとき・iOS で WebView が落ちて開き直したとき・PWA を開き直したときも、3時までなら開いた日の分として数える
- `onSolved` で `countsOnDay` を使う。開いた日の翌日の3時までに解けば、開いた日の分として数え、`addStreak` で連続を1つのばす
- **0〜3時のホーム**: 前の日に開いた事件がまだ解けていなければ、連続の下に「昨日の事件 No.X は捜査の途中です／3時までに解けば、連続日数に数えます」を出す（押すとその事件を開く）。このあいだはホームと事件簿の「連続」も切れていない扱いにする（それまでは、まだ間に合うのに「連続 0 日」と出て、前の日の事件へ行く道もホームに無かった）
- **事件の画面の知らせ**（0.5秒ごとのタイマー）: その日のうちに開いた事件を解いている途中で
  - 日付が変わり、まだ3時前なら「日付が変わりました。3時までに解けば、連続日数に数えます」
  - 3時を過ぎたら「翌朝3時を過ぎたので、この事件は連続日数に数えません」。端末のロック中・スリープ中はタイマーが止まるので、23:50 に開いたままロックして 7:00 に起こした場合は、起きた最初の1回で今の時刻を見て、こちらを出す（「3時までに解けば」を出さない）
  - 3時を過ぎたときは、ホーム・事件簿も描き直す（案内と連続の表示を消す）
- 結果の文: 3時を過ぎて解いたとき、その日のうちに開いた事件なら「翌朝3時を過ぎてから解いた事件は、連続日数に数えません」、そうでなければ今までどおり「当日以外に解いた事件は、連続日数に数えません」
- これまでどおり数えないもの: 3時を過ぎてから解いた／前の日に一度も開いていない事件を、日付が変わってから事件簿で開いた。別のタブで先に解いていた場合の分岐も変えていない
- `openedOnDay` が付く前（この修正の前）に開いた記録には印が無いので、移行の日だけは開き直すと数えない

### 3. 日付が戻ったとき（#13）と、先の日付から戻ったとき

- 西へ移動して日付が1〜2日戻ったときは、表示は「連続 13 日」のまま、戻った日に解いても連続と最後に解いた日を巻き戻さない。元の日付に戻れば、そのまま続けられる
- 守りは時差の幅（2日）だけにした。最初の直しでは幅を決めていなかったので、時計を先の日付（例 2027-01-01）にして1回解くと、時計を戻したあと、その日が来るまで毎日解いても連続が1のまま・最高も増えなくなっていた（直したあとの確認で見つかった）。いまは、最後に解いた日が3日以上先なら時計のずれとみなし、表示は0、解けばその日から1日目として数え直す
- そのかわり、時計を1か月戻してその日の事件を解くと、連続は1日目からになる（最高連続は残る。解かずに元へ戻せば連続はそのまま）。どちらの時計が正しいかは分からないので、「連続が何か月も止まったまま」にならないことを優先した。サポートページにも「端末の日付を手で大きく動かして解いた場合も、連続日数は1日目からになることがあります」と書いた

### 4. No.1 より前の日付（#14）

- `today()` に下限を付けたので、ホーム・事件の上部・結果・共有の文・共有画像・画像のファイル名・事件簿が、すべて No.1 として出る（負の番号は出ない）
- 丸める前の日付（`rawToday()`）が No.1 より前なら、ホーム（連続の下）と事件簿（合計の下）に「端末の日付が 2026年10月1日より前です／日付を確かめてください。いまは No.1（10月1日）の事件を出しています。」を出す。最初の直しで足した「事件簿の一覧が0件のときの案内」は、丸めのせいで一覧が空にならず出ることが無かったので、こちらに置き換えた

### 5. トーストを折り返す

トーストは1行のまま（`white-space:nowrap`）だったので、長い文がスマホ幅（375px）からはみ出していた（既存の「共有できませんでした。画像を保存してから共有してください」も同じ）。幅を画面の内側（左右16px）までにし、長いときは2行に折り返すようにした。角の丸みを 999px から 22px に変えた（1行のときは今までどおり丸く見える）。

### 6. 説明の文

3時までの決まりを、知らせのトーストだけでなく、利用者が読む文にも入れた。

- アプリの遊び方: 「その日のうちに解くと「連続日数」がのびます。夜に開いた事件は、0時を過ぎても翌朝3時までに解けば、開いた日の分として数えます。」
- 事件簿の注記: 「過去の日の事件も遊べます（連続日数には数えません。ただし、その日のうちに開いた事件は、翌朝3時までに解けば数えます）。」
- `support.html`（App Store のサポート URL でもある）: 遊び方の曜日の表の下に同じ説明を足した。よくある質問「連続日数が途切れました」に、3時までの決まり・開き直しても同じこと・0〜3時のホームの案内・時計を大きく動かしたときのことを足した。「前の日の事件は遊べますか」の答えにも3時までの例外を足した（ページなので `sw.js` の版は上げていない）

### 7. 検査 `tools/check-app.mjs`（新規）

`node tools/check-app.mjs index.html` で47項目を確かめる。上の関数を、指摘で再現した場面そのもので動かす。

- 0時をまたぐ: 10-10 に開いて 10-11 00:00 に解く→連続5、3時を過ぎたら数えない、前の日に開いていない事件は数えない
- 開き直す: 10-09 を解いて連続1 → 10-10 23:59 に開いてホームへ → 0時過ぎのホームに案内が出て連続1のまま → 開き直して 00:00 に解く→連続2。読み込み直し（保存の JSON を通す）でも同じ。3時を過ぎたら案内は出ず連続0。3時過ぎに起こしたときは「3時までに解けば」にしない
- 戻る: 連続13で日付が1日・2日戻る、01-03 だけ解いて西へ移動して 01-02・01-04 と解く、時計を 2026-12-01 に戻す（解かずに戻せば13のまま・解くと1から、最高13は残る）
- 先へ進めて戻す: 連続5のまま 2027-01-01 で解き、10-10〜10-20 を毎日解く→1から11までのびる（最高11）。2日先までなら巻き戻さない
- No.1 より前: 2026-09-25・1970-01-01 などは No.1、案内を出す対象
- あわせて、画面のコードに直しが残っているか（`openedOnDay` の保存と読み込み、ホームの案内、知らせの出し分け、#0011 の直し）をソースで確かめる

守りを外した写し（巻き戻さない幅を無くす・記録の `openedOnDay` を見ない・0〜3時の扱いを外す）では、それぞれ該当の項目が FAIL することを確かめた。

## 直したあとの確認で直したこと（2026-10-09）

| 指摘 | 内容 | 直し |
|---|---|---|
| 漏れ（major） | 「その日のうちに開いた」がメモリ上にしか無く、ホームに戻る・読み込み直すと、0時過ぎに解いても数えなかった。0〜3時のホームは「連続 0 日」で、前の日の事件へ行く道も無かった | 2章（記録に残す・ホームの案内・連続の表示） |
| 文 | サポートページ・遊び方・事件簿の文に3時までの決まりが無かった | 6章 |
| 守りの副作用 | 時計を先へ進めて1回解くと、戻したあと連続が増えなくなった | 3章（守りを時差の幅2日に限る） |
| 効かない案内 | 事件簿が空のときの案内は、丸めのせいで出ることが無かった | 4章（丸める前の日付で判断する案内に置き換え） |
| 知らせ | 3時を過ぎて端末を起こしたときも「3時までに解けば」と出た | 2章（今の時刻で出し分け） |

## 直さなかったもの・理由

- **日付を大きく戻して解いたときの連続**: 3章のとおり、時計を1か月戻してその日の事件を解くと、連続は1日目からになる。両方の場面で連続を守るには、解いた日の一覧から数え直す作りに変える必要があるので、清武さんの判断に回した（#0016 の4）
- **生成を速くする・遠い日付の `dailyConfig` を速くする**: 問題の作り方が変わり、全員の日替わり問題が変わるので見送った（#0012・#0016）
- この点検で挙がったそのほかの指摘（不具合ではないと判断したもの・あったら良い機能）は、#0011 の「直さなかったもの・理由」にまとめた
