# 同じドメインのほかのアプリにオフライン用キャッシュを消されても入れ直す

- 管理番号: #0013
- 種類: BUG（バグ修正）
- 対象: PWA（`sw.js`）
- 作成日: 2026-10-09
- 関連: #0005（PWA化）、#0008（公開）、#0016（点検の報告。指摘 #34）

## 概要

ブラウザのキャッシュの置き場所（Cache Storage）はドメインごとに1つで、`kiyotake1229.github.io` の全アプリが共有している。同じドメインのほかのアプリ（公開中の10本: nagi-pond・mahjong・senda・sonaecho・renban・dusk-highway・goi-dojo・habit-app・task-manager・dodge-game）の Service Worker は、自分以外のキャッシュを**全部**消す書き方になっている。そのため、それらを初めて開いたときや版を上げたときに、嘘つき村のオフライン用キャッシュ（`usotsuki-app-v2`）も消え、そのあと通信なしで開くと「このサイトにアクセスできません」になっていた。通信ありで開き直しても、戻るのはそのとき読んだページだけで、`index.html`・アイコン・`support.html` などは戻らなかった。

嘘つき村の側で、**ページを開くたび（通信できるとき）に、先にキャッシュするファイルのうち無くなったものだけを取り直す**ようにした。

## 対象ファイル

- `sw.js`

## 変更内容

- `refill()` を足した。`PRECACHE` の7件（`./`・`index.html`・`manifest.json`・アイコン3つ・`support.html`）を1件ずつ `cache.match` で確かめ、無いものだけを `cache: 'reload'` で取り直して入れる。取れなければ何もしない（次に開いたときにまた試す）
- ページの読み込み（`page()`）で、ネットから届いてキャッシュを新しくしたあとに `refill()` を呼ぶ（`event.waitUntil` の中。表示は待たせない）
- 冒頭の説明に「ほかのアプリに消されても入れ直す」を書いた
- `VERSION`（`v2`）は上げていない。`sw.js` の中身が変わったので、ブラウザは自動で新しい Service Worker に入れ替える。上げると全部のキャッシュを取り直すだけで、効き目は同じ

消された直後に通信なしで開いた場合は防げない（一度つながった状態で開けば元に戻る）。根本の直し方は、兄弟アプリの activate を「自分の名前で始まるキャッシュだけを消す」形にそろえること（例: `ks.filter(k => k.startsWith('kotsu-') && k !== CACHE)`）。これはほかのプロジェクトの変更なので、別の作業として #0016 に残した。

## 確認

- アプリ内のブラウザ（http://127.0.0.1:8793/）: 新しい `sw.js` が動いている状態で、キャッシュ `usotsuki-app-v2` を消した（兄弟アプリに消されたのと同じ状態）→ ページを読み込み直す → `usotsuki-app-v2` に7件（`/`・`/index.html`・`/manifest.json`・`/icon-192.png`・`/icon-512.png`・`/apple-touch-icon.png`・`/support.html`）が戻った。書体のキャッシュ（`usotsuki-fonts-v1`）は消えていない
- `node -e` で `sw.js` の構文を確かめた
- 点検のときに、兄弟アプリ（habit-app）を開いたあとの再現と、この直しで7件が戻ることを、ヘッドレスの Chrome でも確かめている
