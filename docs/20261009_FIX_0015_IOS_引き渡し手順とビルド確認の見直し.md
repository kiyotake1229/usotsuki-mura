# 引き渡し手順とビルド確認の見直し（Xcode の版・EU の申告・審査の連絡先・問い合わせ先）

- 管理番号: #0015
- 種類: FIX（軽微な修正）
- 対象: iOS アプリ（IOS。`ios-app/岩崎さんへの引き渡し手順.md`・`.github/workflows/ios-build.yml`）
- 作成日: 2026-10-09
- 関連: #0006（iOS アプリ化）、#0008（ビルド確認）、#0016（点検の報告。指摘 #3・#36・#40）

## 概要

引き渡し手順書だけで申請まで進めるよう、点検で見つかった抜けを足した。アプリのコードは変えていない。

1. **Xcode 27 でビルドすると起動しないおそれ**（指摘 #36・major）。このプロジェクトは Capacitor 7 の雛形のままで、iOS の UIScene に対応していない。Apple は「最新の SDK（Xcode 27）でビルドしたアプリは UIScene に対応していないと起動しない」としており、手順書は「Xcode 26 以降」だったので、Mac App Store から最新の Xcode 27 を入れると落ちるアプリができる。当面は Xcode 26 でビルドするよう手順書と CI を直した。UIScene への対応そのものは 2027年4月（申請に Xcode 27 が必須になる見込み）までに行う
2. **EU の取引業者（trader）の申告と、App Review の連絡先が手順に無い**（#40）
3. **サポート URL にメールの連絡先が無い**（#3・major）。アドレスは清武さんが決めるので、ここでは「申請前に確かめること」として手順書に足しただけ

## 対象ファイル

- `ios-app/岩崎さんへの引き渡し手順.md`
- `.github/workflows/ios-build.yml`

## 変更内容

### 1. Xcode の版（#36 の当面の対処）

- 手順書2章「必要な環境」を「Xcode 26.x（GitHub Actions の 26.6 でビルド確認済み）」にし、**Xcode 27 は使わない**こと、理由、Xcode 26.x の入れ方（Apple Developer の More Downloads から。複数の Xcode は並べて置ける）、2027年4月ごろまでは Xcode 26 で申請できることを書いた
- CI（`ios-build.yml`）の `runs-on` を `macos-latest` から **`macos-26`** に固定した。さらに「Select Xcode 26」の手順を足し、ランナーの既定の Xcode が 26 でなければ `/Applications/Xcode_26*.app` を選び直す（無ければ失敗にする）。`macos-latest` の既定が Xcode 27 に変わっても、引き渡す手順（Xcode 26）でビルドが通ることを確かめ続けられる

### 2. EU の取引業者の申告と審査の連絡先（#40）

- 手順書5章の先頭に「最初の申請の前に1回だけ（アカウント単位）」として、App Store Connect の「ビジネス」→ 契約 → コンプライアンス → Digital Services Act での trader status の申告を書いた。EU で配信しなくても申告が要ること、会社として出すなら trader で、D-U-N-S の住所と入力した電話・メールが EU の製品ページに出ること、確認コードと書類（登記簿謄本など）が要り数日かかることがあること、出したくなければ配信国から EU を外すことになる（申告自体は要る）こと
- 5章の5「App Review に関する情報」に、必須の連絡先（氏名・メール・電話。電話は +81 から始まる国際形式。利用者には出ない）を足した
- 5章の6「配信国」に、EU を含めるなら申告が済んでいること、を足した

### 3. 問い合わせ先の確認（#3）

- 手順書6章「サポート URL」の注記に、申請前の確認として「お問い合わせにメールの連絡先が載っていること」を足した（審査ガイドライン 1.5。2026-10-09 時点では GitHub の Issues だけなので、清武さんがアドレスを決めて載せるまでは申請しない）
- 7章「審査で見られやすい点」に 1.5 を足した
- `support.html` のメールのカード・プライバシーポリシー7章のアドレスは、アドレスが決まるまで足していない（勝手に決めない）

### 4. Xcode 26 が動く macOS の範囲（直したあとの確認で追記・2026-10-09）

手順書2章は「macOS Sequoia 15.6 以降」と下限しか書いていなかった。Apple の対応表（https://developer.apple.com/support/xcode/ 、2026-10-09 に確認）では次のとおりで、手順書のままでは岩崎さんの Mac によってはビルドできない。

| Xcode | 動く macOS（Apple の表） |
|---|---|
| Xcode 26.6・26.5・26.4.1 | macOS Tahoe 26.2 〜 26.x |
| Xcode 26.3 以前の 26.x | macOS Sequoia 15.6 〜 Tahoe 26.x |
| Xcode 27 | macOS Tahoe 26.6 以降 |

- **macOS 27 は Xcode 26.x の対象に入っていない**（表の上限が「Tahoe 26.x」）。実際に起動しないかは確かめられていない（手元の Mac には Xcode が無い。なお、この Mac 自体が macOS 27.0.1）。以前も、一つ前の Xcode が新しい macOS で動かなかったことがある
- Sequoia（15.x）の Mac では、CI と同じ 26.6 は入らない（26.4.1 から Tahoe 26.2 以上が必要）
- 手順書2章に、Mac の macOS ごとに使う Xcode の表（Tahoe 26.2〜26.x → 26.6、Sequoia 15.6〜15.x → 26.3、macOS 27 以降 → ビルドの前に清武へ連絡）を足した。macOS 27 で Xcode 26 が使えないときに、代わりに Xcode 27 でビルドして申請しないこと（UIScene 未対応で起動しないおそれ）、そのときは UIScene への対応を前倒しすることも書いた
- CI は `macos-26`（Xcode 26.6）なので、この問題は CI では気づけない。#0016 の「決めてほしいこと 3」に、macOS 27 の Mac しか無いなら UIScene への対応を前倒しする必要があることを足した

## 確認

- Apple の対応表（上の URL）を読み、Xcode 26.x・27 の行と、16.x の行（上限が書かれていること）を確かめた
- `ios-build.yml` を YAML として読めることを確かめた（ruby の YAML）。手順の並び: checkout → setup-node → Select Xcode 26 → Versions → … → 実機向けビルド → バンドルの確認
- GitHub Actions（push 後・2026-10-09）: https://github.com/kiyotake1229/usotsuki-mura/actions/runs/37939136085 が成功。ランナーは `macos-26-arm64`、「Select Xcode 26」は「既定の Xcode 26.6 を使う」（Build version 17F113）。シミュレータ向け（Debug）・実機向け（Release）とも `** BUILD SUCCEEDED **`、バンドルの確認も通った
- 手順書の該当の章を読み直し、ほかの章と食い違いが無いことを確かめた
