## 変更内容

### 1. アイコン（`icon.svg` と PNG）

- 図柄: 藍の和紙の紙面に、朱の丸い判子「嘘」（白抜き、明朝の Shippori Mincho B1 の極太）。アプリの判子（`sealSVG`）とファビコンと同じ形。判子は少し傾け、朱肉のかすれと紙の繊維を SVG のフィルタで付けた
- 色: 紙面 `#2C4C8C`→`#1C3266`→`#0F1D3E`（アプリの藍 `--ai` / `--ai-deep` の系統）、朱 `#D3412A`（`--shu`）、判子の白 `#FBF6F0`（`--seal-paper`）
- 角丸は付けない（iOS・Android が付ける）。四隅まで紙面で塗り、透明な部分は無い
- 判子は影も含めて中心から半径 約370px（1024px のとき）に収めた。Android の丸いマスク（安全域は半径 409.6px）でも欠けないので、同じ PNG を `any` と `maskable` の両方に使う
- 180px（apple-touch-icon）でも「嘘」の字が読めることを確かめた

書き出し（このフォルダで実行。Google Chrome・Python 3 と Pillow・書体を読むための通信が必要）:

```bash
python3 tools/make-images.py          # アイコンと OGP の両方
python3 tools/make-images.py icons    # アイコンだけ
python3 tools/make-images.py ogp      # OGP 画像だけ
```

- Chrome の画面なしモードで 1024px を1回だけ描き、Pillow で 512 / 192 / 180 に縮める。すべて透明なし（RGB）
- 書体（Shippori Mincho B1）が読めなかったときは、違う書体のまま書き出さずに止まる（画像の中央の色と四隅の色も確かめる）
- 作業用のファイルは一時フォルダに作り、終わったら消す
- この環境では、撮り終えても Chrome が終わらないことがある。道具は「bytes written to file」が出たら Chrome を終わらせる

`icon.svg` は書体を `<text>` で指定している（明朝の書体の名前を並べた）。書体の無い環境で SVG を直接開くと別の明朝で出るため、manifest には SVG を入れず PNG だけを並べた。

### 3. `sw.js`（Service Worker）

| 対象 | やり方 |
|---|---|
| 先にキャッシュ（install） | `./`・`index.html`・`manifest.json`・`icon-192.png`・`icon-512.png`・`apple-touch-icon.png`・`support.html`（#0007 で追加）。HTTP のキャッシュを通さずに取る（`cache: 'reload'`） |
| ページ（画面の読み込み） | **ネット優先**。取れたらキャッシュを新しくする。オフライン、またはサーバーが 5xx のときはキャッシュ。4秒たっても返事が無ければキャッシュを先に出し、届いた新しい版はキャッシュに入れておく。`?` 以降は無視してキャッシュを探す。キャッシュに無いページの代わりに `index.html` を出すのは、アプリのページ（`./` と `./index.html`）のときだけ（#0007。それまでは support.html や存在しない URL にもアプリの画面を出していた）。Navigation Preload を使う（対応ブラウザだけ） |
| 同じ場所のほかのファイル | キャッシュ優先（無ければネットから取って入れる） |
| 書体の CSS（fonts.googleapis.com） | **stale-while-revalidate**（キャッシュをすぐ出し、裏で新しいものに入れ替える）。`<link>` で読む CSS は中身の見えない形（opaque）で届くので、それも入れる |
| 書体のファイル（fonts.gstatic.com） | キャッシュ優先。URL ごとに中身が変わらないので、毎回取り直して書き直すことはしない（日本語の書体は1画面で50個ほどのファイルに分かれていて、毎回書き直すと端末への書き込みが多くなるため。Google の Workbox の定番の設定と同じ） |
| 書体のキャッシュの上限 | 400件。超えたら古く入れたものから消す |
| 古いキャッシュ（activate） | 名前が `usotsuki-` で始まり、いまの版でないものだけ消す。github.io は同じドメインにほかのアプリも載るので、ほかのアプリのキャッシュには触らない |

キャッシュの名前: `usotsuki-app-v2`（アプリ。#0007 で support.html を足したので v1→v2）、`usotsuki-fonts-v1`（書体。アプリの版を上げても消さない）。

版の上げ方:

- `index.html` を直しただけ → 何もしない（ページはネット優先なので、次に開いたときに届く）
- `manifest.json`・アイコン・先にキャッシュするファイルの一覧を変えた → `sw.js` の `VERSION` を1つ上げる（いまは `v2` なので次は `v3`）
- 書体の指定を変えた → `FONT_CACHE` を `usotsuki-fonts-v2` に

### 5. サポートページ（`support.html`）

- アプリと同じ見た目（藍・朱・和紙のトークン、Shippori Mincho B1 と Zen Kaku Gothic New、夜明けの村の絵。ライト／ダークは端末の設定に合わせる）。1ファイルで完結（画像ファイルを使わず、アイコンも SVG で描く）
- 中身: アプリについて／遊び方の要点（きまり・判子の見本・曜日の表・練習と難問）／よくある質問10件（開閉式。#0007 で「難問」を追加）／通知について／プライバシーポリシー（制定日 2026年10月8日）／お問い合わせ（GitHub の Issues: https://github.com/kiyotake1229/usotsuki-mura/issues ）
- プライバシーポリシーの要点: 個人情報を集めない・登録なし・解析や広告なし／記録は端末の中（localStorage、iOS アプリはアプリの保存領域）だけ／Google Fonts から書体を読むときに IP アドレスなどが Google に届くこと（記録や操作の内容は含まない）／「結果をコピー」はクリップボードに入れるだけ／「画像で共有」「X に投稿」は利用者が選んだ先にだけ結果の文と画像が渡る（#0007 で追加）／端末に保存する設定に通知の設定も含む（#0007 で追加）
- 通知: ブラウザ版は使わない。iOS アプリ版の「毎朝の通知」と「夜の念押し」（20:00。未解決の日だけ）は ON にしたときだけの端末内の通知（ローカル通知）で、外部と通信しない。止め方は iPhone の「設定」→「通知」→「嘘つき村」（#0007 で、呼び方をアプリに合わせ、夜の念押しと iPhone での表示名を直した）
- Issues は公開されるので、個人情報を書かないよう注意書きを入れた
- 動き: 章が順に浮き上がる、アイコンが判子のように押される、よくある質問の開閉、ボタン・目次のホバー。`prefers-reduced-motion` では止める

### 6. index.html に足すもの（この作業では入れていない）

`index.html` は別の作業で並行して直しているため、足すタグとコードはスニペットとして渡した（作業用フォルダの `pwa-snippets.md`）。要点:

- `<head>`: 説明文の更新、theme-color をライト用（`#E7ECF2`）・ダーク用（`#0B1220`）の2つに（`media` 付き）、`apple-touch-icon`、`manifest`、`apple-mobile-web-app-*`（題名「嘘つき村」、ステータスバーは `default`。`black-translucent` だとライトの紙面で時計の文字が白くて読めないため）、`canonical`、OGP・Twitter カード（画像は絶対 URL）
- `applyTheme()`: テーマを固定したときは theme-color を2つともその色に、自動のときはライト用・ダーク用に戻す
- Service Worker の登録: `boot()` の中の目印のコメントの場所で `registerSW()` を呼ぶ。iOS アプリ（`NATIVE`）、iframe の中（Claude Artifact）、origin の無い sandbox、http(s) 以外、安全でない接続、Service Worker の無いブラウザでは登録しない。画面の表示が終わってから（`load` のあと）登録し、失敗しても何もしない

### 7. index.html への組み込み（統合。2026-10-08）

上の6章のスニペットを、統合の作業で `index.html` にそのまま入れた。

- `<head>`（7〜32行目）: 説明文・theme-color 2つ・apple-touch-icon・manifest・`apple-mobile-web-app-*`・canonical・OGP・Twitter カード
- `applyTheme()`: theme-color の書き換えを2つの meta に（`requestAnimationFrame` で `--sky` を読む形から、色を直接入れる形に）
- `registerSW()` を `boot()` のすぐ上に足し、`boot()` の目印のコメントを `registerSW();` に置き換えた
- 任意の D も入れた: 設定画面のいちばん下の説明文の後に「サポート・プライバシーポリシー」のリンク（`https://kiyotake1229.github.io/usotsuki-mura/support.html`、別のタブで開く）。行頭に「?」のアイコン（SVG の `i-q`）、文字は `--ink-2` に下線、ホバー・焦点で朱（`--shu-ink`）に変わる（クラス `.about-link`）

## 確認

`index.html` にスニペットを当てた写しを作業用フォルダに作り、ローカルのサーバー（http://127.0.0.1:8795/ 。確認用。今は止めてある）で確かめた。Claude の確認用ブラウザ（アプリ内の Browser）は Service Worker のファイルを読めない環境だったため、Service Worker の動きは Google Chrome の画面なしモードを DevTools Protocol で動かして確かめた（音は出していない）。

- 1回目の読み込み: Service Worker が activated になり、ページを制御する。`usotsuki-app-v1` に6件（`/`・`index.html`・manifest・アイコン3つ）
- 2回目の読み込み: `usotsuki-fonts-v1` に57件（書体の CSS 1件＋書体のファイル56件）
- オフライン（ローカルのサーバーを止め、外のドメインはすべて引けない設定の Chrome で開き直す）: アプリが開き、今日の事件「時計台の針が1時間進んだ」が出る。明朝の書体もキャッシュから読めた（読み込まれた書体56）。`?from=share#x` 付きの URL でも開ける
- 遅い回線（サーバーが7秒待たせる）: 約4.1秒でキャッシュのページが開く
- 版を上げる（`v1`→`v2`）: `usotsuki-app-v1` が消えて `usotsuki-app-v2` ができる。`usotsuki-fonts-v1` と、ほかのアプリを想定して作ったキャッシュ `senda-v2` は残る
- iframe の中（`sandbox="allow-scripts"` と普通の iframe の両方）: 登録しない。エラーも出ない
- manifest: 名前・短い名前・アイコン（any 2つ・maskable 2つ）を読めた
- theme-color（Browser・360px）: 自動＝`#E7ECF2`／`#0B1220`、ダーク固定＝両方 `#0B1220`、ライト固定＝両方 `#E7ECF2`
- `support.html`（Browser）: 375px（ライト）と 360px（ダーク）で横スクロールなし。曜日の表・判子の見本・質問の開閉・お問い合わせの札を確認
- アイコン: 1024 / 512 / 192 / 180 を目で確認。Android の丸いマスクで切った見本でも判子が欠けない
- `node --check sw.js`、`manifest.json` の読み込み、`icon.svg` の XML の検査: いずれも問題なし
- `node tools/check-engine.mjs`（`--count 30 --days 20`）: スニペットを当てた写しと、今の `index.html` で結果は同じ。3〜6人の項目はすべて PASS。FAIL の2項目（「7〜9人: Engine.LIMITS」「Worker: self.Engine」）は、並行して進めている9人対応の検査がまだエンジンに入っていないためで、この作業とは関係しない
- 作業用のファイル（写し・Chrome のプロファイル・確認用の道具）はこのフォルダに置いていない

統合後（`index.html` に入れた後）にアプリ内の Browser（http://127.0.0.1:8793/ ）で確かめたこと（今回はこの Browser でも Service Worker が動いた）:

- `navigator.serviceWorker.ready` で activated・ページを制御。`caches.keys()` は `usotsuki-app-v1`（`/`・`index.html`・`manifest.json`・アイコン3つ）と `usotsuki-fonts-v1`（書体の CSS とファイル 55件）。キャッシュの `index.html` は9人対応エンジン入りの新しいもの

- 設定のサポートのリンク: ライト・ダークで見え、URL が正しい

## 既知の注意点

- **同じドメインのほかのアプリの Service Worker が、このアプリのキャッシュを消す。** `kiyotake1229.github.io` にはほかのアプリ（閃打 `/senda/` など）も載っている。閃打・語彙道場・habit・mahjong・リラックス・動画編集・マッチングアプリ・そなえ帳の `sw.js` は、activate のときに「自分以外のキャッシュをすべて」消している（`caches.keys()` → `k !== CACHE` を全部削除。MAZE は `maze-` で始まるものだけ消すので問題ない）。そのアプリの版が上がると、このアプリのキャッシュも消える。このアプリは次に通信のある状態で開いたときに作り直すが、それまでは通信なしで開けない。ほかのアプリの `sw.js` を「自分の名前の頭で始まるものだけ消す」形に直すのがよい（このアプリの `sw.js` はそうしてある）
- 日本語の書体は文字のまとまりごとのファイルに分かれていて、表示した文字のファイルだけを読む。オフラインで初めて出る文字（新しい事件の文など）は、端末の書体で出ることがある
- ローカル（127.0.0.1）でも Service Worker は登録される。ローカルで確かめたあとは、開発者ツールで登録を解除しておくと、同じポートでほかのアプリを確かめるときに紛らわしくない
- `support.html` の「iOS アプリ版は準備中です」は、App Store に出たら直す（通知の説明は #0007 で iOS アプリ版の実装に合わせた）
- App Store のサポートURLのお問い合わせ先が GitHub の Issues だけだと、アカウントの無い人は連絡できない。必要ならメールの窓口を足す
