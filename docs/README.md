# 嘘つき村の事件簿 開発ドキュメント管理ルール

このファイルは、docs/ フォルダにドキュメントを追加する際のルールを定めています。

ドキュメント一覧: docs/manager/docs.json

---

## 1. 命名規則

```
YYYYMMDD_種類_連番_場所_内容.拡張子
```

例: `20261010_BUG_0002_APP_ヒントの箱が閉じない.md`

- **YYYYMMDD**: 作成日
- **種類**: 案件の種類（下記参照）
- **連番**: 4桁の連番（0001〜9999）
- **場所**: 対象システム（下記参照）
- **内容**: 内容がわかる日本語名

---

## 2. 種類（Type）略語一覧

| 略語 | 意味 | 説明 |
|------|------|------|
| INQ | Inquiry | お問い合わせ対応・調査 |
| BUG | Bug Fix | バグ修正 |
| FIX | Fix | 軽微な修正 |
| NEW | New Feature | 新規開発 |
| ENH | Enhancement | 機能改善・拡張 |
| SEC | Security | セキュリティ対応 |
| DOC | Document | ドキュメント作成 |
| REF | Refactor | リファクタリング |
| DPL | Deploy | デプロイ関連 |
| RPT | Report | 報告書・見積書 |
| UPD | Update | 既存機能の更新 |

---

## 3. 場所（Category）略語一覧

| 略語 | 対象システム |
|------|-------------|
| ALL | プロジェクト全体 |
| APP | 画面（`index.html` のうち推論エンジン以外。HTML・CSS・画面の JavaScript・似顔絵・効果音・保存） |
| ENG | 推論エンジン・問題生成（`index.html` 内の `// ==ENGINE START==`〜`// ==ENGINE END==`）と、その検査 `tools/check-engine.mjs` |
| PWA | PWA と公開用の素材（`manifest.json` / `sw.js` / アイコン / `ogp.png` / `support.html` / `_config.yml`） |
| IOS | iOSアプリ（`ios-app/`。Capacitor 7）と、そのビルド確認（`.github/workflows/ios-build.yml`） |

ENG を変えて問題の作り方が変わる（同じ日付で別の問題になる）ときは、文書に「日替わりの問題が変わる」ことと、エンジンの `VERSION` を上げたことを必ず書く。

---

## 4. 連番管理

- 連番は全ドキュメント共通で管理（場所や種類で分けない）
- 関連案件は同じ連番を使用するか、ファイル内で関連番号を記載
- 次の連番は `docs/manager/docs.json` の `next_no` で確認

例: お問い合わせ→バグ修正の流れ
```
20261010_INQ_0002_ENG_同じ日に別の問題が出る報告.md
20261011_BUG_0002_ENG_日付の扱いの修正.md  ← 同じ連番で関連付け
```

### docs.json の更新（重要）

ドキュメントを作成・編集した後は、必ず以下のコマンドを実行すること:

```bash
bash docs/manager/generate_docs_json.sh
```

---

## 5. ファイル配置

すべてのドキュメントは `docs/` 直下に配置する。サブフォルダは使用しない。

管理用ファイル:
- `docs/README.md` — このファイル（ルール説明）
- `docs/manager/` — 管理スクリプト・データ

---

## 6. 必須記載項目

ドキュメントには以下の項目を必ず記載すること:

### (1) ヘッダー情報
管理番号、種類、対象システム、作成日、関連案件

### (2) 概要
何についてのドキュメントか（1〜3文）

### (3) 対象ファイル
関連するソースコードファイルのパスを記載

### (4) 変更内容（変更の場合）
何をどう変更したか

### (5) 確認URL（動作確認が必要な場合）

| 環境 | URL |
|------|-----|
| ローカル | http://127.0.0.1:8793/ （このフォルダで `python3 -m http.server 8793 --bind 127.0.0.1`） |
| 開発確認用 | Claude Artifact の URL（公開後） |
| 本番 | GitHub Pages の URL（公開後） |

### (6) 作業概要と概算費用（作業が発生する場合）

| 項目 | 内容 | 工数 |
|------|------|------|
| 調査 | ... | Xh |
| 実装 | ... | Xh |
| テスト | ... | Xh |
| 合計 | | Xh（Y人日） |

- 工数は時間（h）で書き、8h = 1人日で換算する
- 人日単価は未設定のため、金額は書かない（単価が決まったら「概算費用」の行を追記する）
- 外部費用（Apple Developer Program など）は表の下に別に書く

## 7. gitコミット時のルール

2026-10-08 から git で管理している（GitHub の `kiyotake1229/usotsuki-mura`。#0008）。文書を作って `generate_docs_json.sh` を実行してから、下のルールでコミットする。

### コミット前チェックリスト

| 変更種類 | ドキュメント | 必須度 |
|----------|-------------|--------|
| 新機能追加 (NEW) | 必須 | ◎ |
| バグ修正 (BUG) | 必須 | ◎ |
| 機能改善 (ENH) | 必須 | ◎ |
| セキュリティ対応 (SEC) | 必須 | ◎ |
| 軽微な修正 (FIX) | 推奨 | ○ |
| リファクタリング (REF) | 状況による | △ |

### コミットメッセージ規則

```
[#連番] 変更内容の要約

- 変更ファイル一覧
- 関連ドキュメント: docs/YYYYMMDD_TYPE_NNNN_CAT_タイトル.md
```

ドキュメント不要の場合:
```
[no-doc] タイポ修正: path/to/file
```

### ドキュメント不要の例外

- タイポ修正
- コメントの追加・修正のみ
- コードフォーマットの調整のみ
- 開発環境のみに影響する変更
