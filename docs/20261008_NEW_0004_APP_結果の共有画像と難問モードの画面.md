- 管理番号: #0004

## 概要

解決した結果を1枚の画像（1080×1350 の PNG）にして共有できるようにした。答え（犯人・だれが嘘つきか）は描かない。あわせて、練習に4つ目の「難問（容疑者9人）」の入口と、9人の問題を Web Worker で作る仕組み・7人以上の盤面をつめて見せる表示・名簿を足した。iOS アプリ（Capacitor）のときだけ動くネイティブ連携（触覚・記録の二重保存・毎朝の通知・裏に回ったときの時間停止・画像の共有）も `index.html` に入れた。Web 版の動きは今までと同じ。推論エンジン（ENGINE START〜END）には触れていないので、日替わりの問題は変わらない（`VERSION` はそのまま）。

### 2. 難問（容疑者9人）の画面（C）

**入口**: ホームの練習欄に、★1〜★3 の下に横長の「難問」カード（「9人」の枠・★★★・「容疑者9人の大事件。腰を据えてじっくり」）。

- エンジンが9人に対応していないとき（`Engine.LIMITS.maxPeople` が無い・9未満。いまの `index.html` のエンジン）は、カードに「準備中」と出し、押すと「難問（容疑者9人）は準備中です」の画面（［★3 の練習を開く］［戻る］）。落ちない
- 対応しているときは `Engine.generate({ seed, people: 9, star: 3 })` で作る。作れなかった・人数が違ったときも「準備中」の画面
- 途中は1件だけ残す（保存の `practice.hard`）。手を付けたら「途中」の印。解くと消え、練習で解いた数に足す

**Web Worker で作る**（`genHeavy`）

- `index.html` の中のエンジンの `<script>` の文字から ENGINE START〜END の間を取り出し、「メッセージを受けて `Engine.generate` を呼ぶ」数行を足して Blob にし、`new Worker(URL.createObjectURL(blob))` で動かす。メッセージで `{ seed, people, star }` を渡し、問題を JSON の文字で受け取る
- Worker は読み込めたら最初に `{ ready: true }` を返す。作れない・読めない（`Worker` が無い、`new Worker` が失敗、`error` が出る、2.5秒たっても ready が来ない。Claude Artifact の制限など）ときは、メインスレッドで同じ関数を呼ぶ（同じ seed なら同じ問題）
- 画面を離れたら Worker を止める（`cancelHeavy`）
- 待つ間は「事件ファイルを用意しています」に、進み具合の帯（エンジンは途中経過を返さないので、時間に合わせて9割まで進め、できたら満たす）と「容疑者9人の大事件。答えが1つに決まり、順に考えれば解けるかを確かめています（n秒）」。#0007 で、帯のタイマーが始めた直後に止まっていた不具合（`cancelHeavy` が帯のタイマーまで止めていた）を直し、帯の下地を背景と見分けられる色にした

**7人以上の盤面**（`DENSE_FROM = 7`）

- カードをつめる（`.cards.dense`）: 似顔絵 54→40px、余白・吹き出しの字を少し小さく。判子のボタンは高さ44px を保つ
- 事件画面の見出しの下に「名簿」（`#roster`）: 9人の名前を1行に並べ、それぞれに今の判子（正＝朱の丸、嘘＝朱の輪、犯＝朱の角、未判定＝点線の丸）。押すとそのカードへ移動して光る。3文字の名前（イツキ）は字を小さくして枠に収める
- 9人目の色（#0007 で追加）: エンジンの色は8色なので9人では1人目と9人目が同じ色になる。画面側で、9人目が他の人と同じ色なら9色目（`--p8`。ライト `#8D358D`／ダーク `#E596E2`、似顔絵の服 `#B46BB4`）に置き換える（`startCase`）
- 証言の名前を押したときも、移動先のカードと名簿の同じ人が光る。名簿は見出しと一緒に上に固定されるので、移動先のカードが名簿の下に隠れない（375px で確認）

### 6. index.html 側に入れたネイティブ連携（#0006 から参照）

iOS アプリ（Capacitor）のときだけ動く。Web 版ではどれも何もしない（設定に通知の行も出ない）。参考は `語彙力/index.html` の native bridge。

- 判定: `const NATIVE = !!(window.Capacitor && window.Capacitor.isNativePlatform && window.Capacitor.isNativePlatform())`。プラグインは `window.Capacitor.Plugins` から取る（import しない）。`plug(名前)` が、ネイティブでプラグインがあるときだけそのオブジェクトを返す。無いプラグインの機能は Web と同じ動きに戻る
- 使うプラグインとメソッド

| プラグイン（npm） | メソッド | 使う場面 |
|---|---|---|
| Haptics（`@capacitor/haptics`） | `impact({ style: 'LIGHT' })` / `notification({ type: 'ERROR' })` / `notification({ type: 'SUCCESS' })` | 判子を押す・設定の切り替え / 誤答 / 解決。設定の「振動」OFF で止める |
| Preferences（`@capacitor/preferences`） | `get({ key })` / `set({ key, value })` | 記録の二重保存。キーは localStorage と同じ `usotsuki.v1` |
| LocalNotifications（`@capacitor/local-notifications`） | `checkPermissions()` / `requestPermissions()` / `getPending()` / `cancel({ notifications })` / `schedule({ notifications })` / `addListener('localNotificationActionPerformed')` | 毎朝の通知・夜の念押し・通知を押して開く |
| App（`@capacitor/app`） | `addListener('appStateChange')` | 裏に回ったら経過時間を止めて保存。戻ったら再開・描き直し・通知の予約し直し |
| Share（`@capacitor/share`） | `share({ title, text, files, dialogTitle })` | 結果の画像の共有 |
| Filesystem（`@capacitor/filesystem`） | `writeFile({ path, data, directory: 'CACHE' })` | 画像を一時フォルダに書く（data は PNG の base64） |
| StatusBar（`@capacitor/status-bar`。#0007 で追加） | `setStyle({ style })` | 状態バーの文字色をアプリのテーマに合わせる |

- 記録の二重保存: 保存のたびに localStorage と Preferences の両方に同じ JSON を書く。起動時（`nativeRestore`）に Preferences を読み、localStorage が空か古い（`t` が小さい）ときは Preferences から戻す。逆に Preferences が古ければ localStorage の分で追いつかせる。戻すのを待ってから画面を出す（最長1.2秒）
- 毎朝の通知（設定「毎朝の通知」と時刻。初期 7:00）: ON にしたときだけ許可を求める（許可されなければ OFF に戻し、「通知が許可されていません」と設定の行に案内）。先28日分を1日ずつ予約し、本文にその日の No.・事件名・★・人数を入れる（題「今日の事件が届きました」、本文の例「No.9「ぶどう色の噴水」（★★☆・容疑者6人）。犯人は1人だけ。」）。アプリを開くたび・戻るたびに予約し直すので、毎日開いていれば途切れない。28日開かなければ止まる
- 夜の念押し（設定「夜の念押し」）: 20:00 に「まだ解いていません」（本文「今日の事件 No.8「…」が、あなたの推理を待っています。」）。その日が未解決の日だけ、先7日分。今日を解いたら予約し直して取り消す
- 通知の番号: 毎朝は `710000 + No.`、夜は `720000 + No.`。予約し直すときは、この範囲の予約をまとめて取り消してから入れ直す
- 通知を押してアプリを開いたら、今日の事件を開く
- 経過時間: `appStateChange` で `isActive: false` なら止めて保存、`true` なら再開。これまでの `visibilitychange` もそのまま残している
- Service Worker: `boot()` の中に登録場所の目印のコメントだけ置いた（「Service Worker（PWA）の登録はここに足す。ネイティブ（NATIVE が true）では登録しない」）。登録のコードは #0005 のスニペットを統合のときに入れる
- 設定画面: iOS アプリでは「振動」の説明が「判子・ミス・解決のときに軽く震える」、最下部の説明が「…記録はこの端末のアプリの中だけに保存されます」になる（#0007 で冒頭を「記録や操作の内容を外部に送ることはありません（外から読むのは文字の書体だけで、Google Fonts から読み込みます）」に改めた）
- 状態バー（#0007 で追加）: `StatusBar`（`@capacitor/status-bar`）があれば、`applyTheme()` でテーマに合わせて `setStyle`（ダーク＝`DARK`、ライト＝`LIGHT`、自動＝`DEFAULT`）。起動の0.9秒後とアプリに戻ったときにも当て直す
- 通知の注記（#0007 で変更）: 「通知が許可されていません」は、許可を求めて断られたときに出し、iPhone の設定で許可してアプリに戻ったら消す（毎朝・夜がどちらも OFF でも、予約し直しのたびに許可の状態を確かめる）

- ブラウザ（アプリ内の Browser、375px。音は消してから操作。クリックは JavaScript で行った）
  - 今日の事件を1回間違えてから解く → ［画像で共有］→ この環境は Web Share が無いので画面内に画像が出る。画像を等倍で目で確認: 文字の切れ・はみ出し無し、答え・村人の名前は描かれていない、書体は Shippori Mincho B1 で描けている。ライト・ダークのどちらの設定でも同じ画像で、共有画面・結果画面の見た目も崩れない
  - ［X に投稿］のリンク先の文（上のコピー文と同じ。URL 入り）、［結果をコピー］（この環境はクリップボード不可のため、文を選んだ状態の表示に切り替わる）、Esc・ブラウザの戻るで共有画面だけ閉じて結果が残る、焦点が［画像で共有］に戻る

## 統合で直したこと・確かめたこと（2026-10-08）

#0003 の9人対応エンジンと #0005 の PWA のタグを `index.html` に入れたときに、画面側で1つ直した。

**Worker で作れなかった環境では、次から Worker を試さない**（`genHeavy` と変数 `workerOff`）

- 理由: Claude Artifact のように CSP で blob の Worker が止められる環境では、難問を開くたびに Worker を作ろうとして、コンソールに CSP のエラーが1件ずつ出る。返事が来ない形で止められる環境では、開くたびに2.5秒待ってからメインスレッドに切り替わる
- 直したこと: Worker を試して失敗したら（`new Worker` の例外・`error`・2.5秒たっても ready が来ない）`workerOff` を立て、そのページを開いている間はメインスレッドで作る。うまく動く環境の動きは変わらない

**確認**（アプリ内の Browser、http://127.0.0.1:8793/ 、375px。音は消してから操作）

- 9人対応エンジン入りの `index.html` で、難問カードの「準備中」が消え、Worker の作成 → ready（16〜58ms）→ 問題を受け取る（39〜84ms）。カードがつまり、名簿に9人が並ぶ。ライト・ダークとも
- Worker を3通りに壊して確かめた: `new Worker` が例外を出す／返事をしない Worker（2.5秒後に切り替え、Worker は止める）／CSP `worker-src 'none'` の iframe（Artifact を想定。`error` がすぐ来る）。どれもメインスレッドで同じ問題（同じ seed の「反対向きの道しるべ」）ができ、9人の盤面が出た。CSP の iframe で難問を2回続けて開くと、CSP のエラーは1回目の1件だけになった（直す前は毎回1件）
- 通し: 今日の事件（No.8）を解く → ［画像で共有］（1080×1350 の PNG を等倍で目で確認。答え・村人の名前は描かれていない）→ 難問（9人）を1問、自分で考えて解く → 解説 → 設定でダーク。アプリのコンソールエラーは0件（CSP の iframe で意図的に出した worker-src のエラーだけ）
- 「残った課題」の「9人の問題は準備中のまま」は解消した。Artifact では Worker が止められてもメインスレッドで作る（実際の Artifact では未確認）
