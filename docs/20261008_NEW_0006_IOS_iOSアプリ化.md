## 概要

Web アプリ本体（`index.html`）をそのまま同梱する iOS アプリのプロジェクト `ios-app/` を、`語彙力/ios-app/` を雛形に Capacitor 7 で作った。Bundle ID は `work.ltv.usotsuki`、iPhone・縦向きのみ。`index.html` が使うプラグイン（App・Haptics・LocalNotifications・Preferences・Share・Filesystem）を入れ、`Info.plist`・プライバシーマニフェスト・アイコンと起動画面をそろえた。手元の Mac には Xcode が無いので、ビルドの確認は GitHub Actions の macOS で行う（`set -o pipefail` と「BUILD SUCCEEDED」の確認で、失敗を見逃さない形にした）。岩崎さん向けの `ios-app/岩崎さんへの引き渡し手順.md` も書いた。`index.html` と推論エンジンは変えていないので、日替わりの問題は変わらない（`VERSION` はそのまま）。

### 3. Xcode プロジェクトの生成（`ios/`）

`npm install` → `npm run sync-web` → `npx cap add ios` → `npm run icons` の順で作った。

- `cap add ios` は Podfile（8つの Pod: Capacitor・CapacitorCordova と6プラグイン）を書き、**pod install まで成功**した（`Podfile.lock` あり。Filesystem が使う `IONFilesystemLib 1.1.4` も取得）。最後の `xcodebuild clean` だけが「Xcode が無い」で失敗する。これは Capacitor の CLI が pod install のあとに行う掃除で、Xcode のある環境（GitHub Actions・岩崎さんの Mac）では通る

### 5. iPhone 専用にした（`TARGETED_DEVICE_FAMILY = 1`）

雛形（語彙力・habit）は iPhone / iPad の両対応だが、このアプリは iPhone 専用にした。iPad では iPhone 用の画面のまま動く。

- iPad にも対応すると、申請に iPad（13インチ）のスクリーンショットが要る。共通ルールの3サイズ（iPhone）で済ませるため
- iPad 対応で縦向きだけにするには `UIRequiresFullScreen` が要るが、iPadOS 26 で非推奨になった。iPhone 専用ならこの問題が起きない
- 画面は中央 480px の1列で、iPad の大きな画面を生かす作りになっていない

iPad 対応にするときは、`project.pbxproj` の `TARGETED_DEVICE_FAMILY` を `"1,2"` に戻し、`Info.plist` に `UISupportedInterfaceOrientations~ipad`（4方向）を足し、iPad のスクリーンショットを用意する。

### 6. プライバシーマニフェスト（`PrivacyInfo.xcprivacy`）

Apple は、特定の API を使うアプリに「使う理由」の申告を求める（2024年5月から、無いとアップロードで止まる）。プラグインの説明書どおりに App ターゲットへ入れた。

| 中身 | 値 | 理由 |
|---|---|---|
| `NSPrivacyAccessedAPICategoryUserDefaults` | `CA92.1` | Preferences プラグイン（UserDefaults に保存） |
| `NSPrivacyAccessedAPICategoryFileTimestamp` | `C617.1` | Filesystem プラグイン（ファイルの作成・更新日時を扱う） |
| `NSPrivacyTracking` / `NSPrivacyTrackingDomains` / `NSPrivacyCollectedDataTypes` | false / なし / なし | トラッキングなし・収集データなし |

- Xcode が無いので、CocoaPods に入っている `xcodeproj`（Ruby）で `project.pbxproj` に足した（App グループへの参照と Resources への追加。差分はこの2つと、空の `packageReferences` が消えただけ）
- Capacitor 本体（`Capacitor` / `Cordova`）は自分のマニフェストを持っている。プラグインは持っていないので、アプリ側で申告する

### 7. アイコンと起動画面（`npm run icons`）

- アイコン: `assets/icon.png`（#0005。藍の和紙に朱の判子「嘘」、透明なし）から `AppIcon-512@2x.png`（1024px、透明なし）を作った
- 起動画面: 雛形どおりだとアイコン（角の立った藍の四角）が真ん中に小さく出るだけなので、**判子だけ**をアプリの地の色に置いた画像を作った。ライト `#E7ECF2`、ダーク `#0B1220`（アプリのダークの `--sky`）。iPhone の画面では判子の直径が約100〜140pt。端末がダークのときはダーク版が出る
  - `assets/splash.png` / `splash-dark.png`（2732×2732、透明なし）。`@capacitor/assets` はこの2つがあれば起動画面に使う
  - 作り方: `icon.svg` から紙面の `<rect>` 2つと判子の影の `<circle>` を外した SVG を、`tools/make-images.py` の `ICON_PAGE` と `shoot()` で 1024px に描き（背景をライト・ダークの地の色にする）、600px に縮めて 2732px の地の色の真ん中に置く。アイコンの判子を変えたら同じ手順で作り直し、`npm run icons` を実行する
- Capacitor の雛形の起動画面（`splash-2732x2732*.png`）は使わなくなったので消した

### 8. ビルド確認（`.github/workflows/ios-build.yml`）

語彙力の同名ファイルを元にした。`index.html`・`manifest.json`・`icon.svg`・`icon-*.png`・`apple-touch-icon.png`（アプリに入るファイル。#0007 で追加）・`ios-app/**`・このファイル自身が変わったとき（push）と、手動（workflow_dispatch）で動く。

1. Node 22（npm のキャッシュあり）→ `npm ci` → `npm run sync-web` → `npx cap sync ios`（pod install）
2. 構成の確認: `public/index.html` がある、`sw.js` が入っていない、Bundle ID、`Info.plist` と `PrivacyInfo.xcprivacy` の書式、マニフェストが Resources に入っている、Pods ができた
3. ビルド2本（署名なし）: シミュレータ向け Debug と、実機向け Release（App Store に出す形に近い）
4. できた `App.app` の確認: `index.html` が入っている、`sw.js` が無い、`PrivacyInfo.xcprivacy` がある、Bundle ID、写真への保存の説明文、8つのフレームワーク（Capacitor と7プラグイン。#0007 で CapacitorStatusBar を追加）
5. 失敗したときは `error:` の行を表示し、ログを成果物（7日間）として残す

語彙力との違い（失敗を見逃さないため）:

- 語彙力は `xcodebuild … | tail -30` で、パイプの最後の `tail` の終了コードが使われるため、**ビルドが失敗しても成功に見えるおそれがあった**。今回は `set -o pipefail`（と `shell: bash`）で xcodebuild の失敗をそのまま失敗にし、さらにログに `** BUILD SUCCEEDED **` が無ければ失敗にした
- `LANG` / `LC_ALL` を `en_US.UTF-8` にした（日本語の表示名で CocoaPods が止まらないように）
- 同じブランチで続けて push したら古い実行を止める（concurrency）。40分で打ち切る

手元で、偽の `xcodebuild` を使って「成功」「失敗（終了コード 65）」「終了コード 0 だが BUILD SUCCEEDED が無い」の3通りを流し、0 / 65 / 1 で終わることを確かめた。`App.app` の確認も、偽のアプリの形で通る・フレームワークが1つ欠けると失敗することを確かめた。

## 既知の注意・残作業

- **CI の結果待ち**: 上のとおり。失敗したらログ（成果物 `ios-build-logs`）の `error:` の行を見て直す
- **状態バーの色**: テーマを「ライト」「ダーク」に固定し、端末の設定と逆にしたとき、状態バー（時計など）の文字が背景と同じ系統の色になり読みにくい。→ #0007 で `@capacitor/status-bar` を足し、`applyTheme()` から `setStyle()` を呼ぶようにした（実機での確認はまだ）
- **起動直後の色**: WebView の背景はライトの地の色（`#E7ECF2`）1色。端末がダークのとき、起動画面からホームに切り替わる一瞬に明るい色が見える可能性がある。実機で確かめ、気になれば backgroundColor をダークの色にするか、起動画面を少し長く出す
- **書体の通信**: 書体は Google Fonts から読む（オフラインでは端末の書体）。App Store の「データを収集しません」はこのままで出せる見込みだが、完全に通信をなくし、見た目もそろえるなら、書体（Shippori Mincho B1・Zen Kaku Gothic New。どちらも SIL OFL で同梱できる）を `www/` に入れて `index.html` から読む改修をする
- **support.html の文言**: 「iPhone の『設定』→『通知』→『嘘つき村の事件簿』」とあるが、iPhone の設定に出る名前はホーム画面と同じ「嘘つき村」になる。→ #0007 で「嘘つき村」に直した。「iOS アプリ版は準備中です」は公開時に直す
- **9人の難問**: 9人の問題を Web Worker で作る（#0004）。iOS の WebView（`capacitor://localhost`）で Worker が動くかを実機で確かめる。動かなくてもメインスレッドで作るので遊べる（9人で0.1秒前後の見込み）
- **統合で index.html に入ったもの（2026-10-08）**: Service Worker の登録（`registerSW()`）は `NATIVE` のとき何もしない（`sw.js` も `www/` に入れていないので、どちらにしても動かない）。設定画面の下に「サポート・プライバシーポリシー」のリンク（GitHub Pages の絶対 URL、別のタブで開く形）を入れた。iOS アプリの中で押したとき Safari で開くかを実機で確かめる
- **スクリーンショット**: `ios-app/screenshots/` に 6.7 / 6.5 / 5.5 インチの3サイズ × 6枚（#0007 で作成）
- **申請**: 岩崎さんが `ios-app/岩崎さんへの引き渡し手順.md` に沿って行う（署名・Archive・App Store Connect の入力）
- **ほかのアプリ**: 語彙力・habit の `ios-app/` にはプライバシーマニフェストが無い（Preferences を使っているので、アップロード時に止まるおそれがある）。語彙力の `ios-build.yml` には pipefail が無い。それぞれ直すのがよい
