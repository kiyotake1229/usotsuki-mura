# 文字の選択・別タブでの記録の消去・読み込み直したあとの戻る

- 管理番号: #0011
- 種類: BUG（バグ修正）
- 対象: アプリ本体（APP）
- 作成日: 2026-10-09
- 関連: #0002・#0007（別タブ・戻るの仕組み）、#0016（点検の報告。指摘 #15・#19・#20）

## 概要

画面の小さな不具合を3つ直した。どれもエンジンには触れていないので、日替わり問題・`VERSION` は変わらない。

1. **PC で［推理を提出］などをダブルクリックすると文字の選択が残り、あとで開く共有画像の画面が全部青く塗られて見える**（指摘 #15）。練習カードをトリプルクリックしても、開いた盤面の題名・あらましが選ばれた状態になっていた
2. **別のタブで「記録を消す」と、もう一方のタブが開いていた事件の記録を書き戻す**（#19）。ホームは「1回目で解決」と判子が付くのに「連続 0 日・解決 0件」と食い違い、今日を解き直すこともできなくなっていた
3. **ページを読み込み直したあと、戻るが1回（以上）空振りする**（#20）。Android の引っぱって更新や、裏で捨てられたタブを開き直したときに起こる

## 対象ファイル

- `index.html`（画面の JavaScript と CSS）

## 変更内容

### 1. 文字の選択（#15）

- 選択を消す `clearSel()` を足し、画面を切り替えるとき（`show`）、結果を出すとき（`showResult`）、共有画像の画面を出すとき（`openShareView`）、盤面ができたとき（`startCase`）に呼ぶ
- 押すもの（`.btn`・判子の `.mk`・`.icon-btn`・下のバー・結果と共有画像のボタンの並び・練習カード・事件簿の行・テーマの切り替え・スイッチ・名簿・判子の絵）に `user-select:none` を付け、ダブルクリック・トリプルクリックで選択が始まらないようにした。証言・解説の本文は今までどおり選べる。共有画像（`.sv-img`）の長押し保存もそのまま

### 2. 別のタブでの「記録を消す」（#19）

- 保存データに「消した回の目印」`epoch` を足した。記録を消すたびに新しい値（時刻＋乱数）にする。初めの値は空（`''`）で、古い保存データもそろって空として読む
- 事件を開いたときに、その目印を控える（`P.epoch`）。途中・結果を保存する `saveProgress` は、保存の目印が控えたものと違えば（＝開いたあとに別のタブで消された）何も書かない
- `storage` イベントで目印が変わったと分かったら、開いている事件・結果・共有画像・パネルを閉じ、事件・解説の画面にいればホームへ戻して「別の画面で記録が消されました」と出す
- 消されたあとに解き終えた場合は、新しい記録として数える（stats と記録がそろう）

### 3. 読み込み直したあとの戻る（#20）

起動のとき、今の履歴の項目が `usd:1` 以上（前の画面の履歴が残っている）なら、`history.go(-usd)` でこのアプリの最初の項目（`usd:0`）まで戻ってから始める。戻ったときの popstate は今の画面（ホーム）と同じなので何もしない。後ろに残った古い項目は、次に別の画面へ進むときに切り捨てられる。

- `node tools/check-engine.mjs index.html`: PASS（82項目）

  - #19: タブ B で今日の事件（解決済み）を開いた状態で、タブ A で 設定 → 記録を消す → 消す。タブ B はすぐホームに戻り「別の画面で記録が消されました」、ホームは「未解決・連続 0 日・解決 0件」。タブ B で visibilitychange・pagehide を起こしても、保存の `daily` は空のまま。その後タブ B で事件を開いて判子を押すと、途中の記録は普通に保存された
  - #20: ホーム → 事件簿 → 事件（履歴 `usd:2`）で読み込み直す → ホームが出て、履歴は最初の項目（`usd:0`）。事件簿へ進んで戻るとホーム、その前にはアプリの項目が無い（1回の戻るでアプリの外へ出る）
  - スマホ幅（375px）の通し: 初回起動 → 今日の事件を1回間違えて解く → 共有画像 → 解説 → 事件簿 → 難問（9人）を1問 → 設定でダーク。コンソールのエラー 0 件
- 確認で作った記録は消した（確認用の 127.0.0.1 の保存は空に戻した）

## 直さなかったもの・理由

2026-10-09 の点検（#0016）で挙がった指摘のうち、確かめた結果「不具合ではない」「アプリの中では起こらない」「あったら良い程度」と判断して直さなかったものを、ここにまとめる（この文書の3件に限らず、点検全体の分）。清武さんの判断が要るもの・問題が変わるので見送ったものは #0016 にある。

### 不具合として挙がったが、直さなかったもの

| 指摘 | 理由 |
|---|---|
| 別のタブで同じ★の練習を同時に開くと、練習の途中が入れ替わる・消える | 練習の途中は★ごとに1件だけ残す作りで、最後に保存したタブの内容が残るのは作りどおり（2タブを node で再現して確かめた）。失うのは練習1問の解きかけだけで、解決数・連続日数・日替わりの記録は守られる（#0001 の約束はここまで）。提案の直し方（seed が同じときだけ消す）は、先に自動保存で置き換わるので効かない |
| ★2・6人の問題の生成が、まれに約180msかかって画面が止まる | 指摘の数字は Node の vm の中で測ったもの。実際のブラウザ（Chrome）では同じ5,000問で最大89ms・100ms超は0問。事件を開くときは「事件ファイルを用意しています」を最低0.38秒出すので、その中に収まり、開くまでの時間は延びない。速くすると問題の作り方が変わる（#0016 の「見送ったもの」） |
| 遠い先の日付ほど `dailyConfig` が遅くなる | 2036年でも最初の1回が約45ms（起動1回につき1度だけ）。秒単位になるのは端末の時計が数十年以上先にずれたときだけ。外から日付を入れる道は無く、結果は正しい |
| エンジンに極端な入力（穴のある配列・NaN の seed・NaN の日数）を渡すと、矛盾した文や壊れた値を返す | アプリはこれらを渡さない。`check` の呼び出しは1か所で、いつも穴の無い配列。seed は保存から読むときに文字列か数字かを確かめる。`addDays` はいつも整数で呼ぶ |
| 画面に出す `parts`・`refs` と語尾が話し方に合うかを検査していない | 証言の `text` は `parts` から組み立てる作りで、ずれようがない。日替わり365日などの計3,809証言で、不一致0を確かめた。将来の書き換えに備えた検査の追加は今後の候補 |
| 記録を保存できない環境・保存に失敗したときに知らせない | 保存できなくてもメモリ上で遊べるのは、#0001 6章で決めた動き。保存する記録はとても小さい。知らせを出すかは、下の「記録を消えにくくする」とまとめて今後の候補にした |
| `ios-app/www/` と `ios-app/ios/App/App/public/` の `index.html` が古い（#0009 より前） | git の対象外の中間ファイルで、ビルドの前に必ず `npm run sync` で作り直す（CI も引き渡し手順も）。違いは #0009 の「画像を保存」の条件だけで、iOS アプリの中ではどちらも同じ動き |
| 引き渡し手順の「Node.js 20 以降」と、`npm install` で出る脆弱性の警告 | 警告は開発用の `@capacitor/assets` の中だけで、アプリには入らない（`--omit=dev` で0件）。`npm audit fix --force` を流しても何も変わらない。Node 20 は `@capacitor/cli` 7.6.9 の最低条件どおり（無ければ LTS を入れる、と書いてある） |
| GitHub Actions の Node 20 の非推奨の警告（`checkout@v4`・`setup-node@v4`・`upload-artifact@v4`） | Node 20 の取り外し（2026-09-23）のあとも、v4 は Node 24 で動いて成功している（警告だけ）。このワークフローはビルド確認用で、申請には使わない。版を上げるのは保守として今後 |

### 足りない機能として挙がったが、今回は入れなかったもの（あったら良い・今後の候補）

| 指摘 | 理由 |
|---|---|
| 記録の引き継ぎ（書き出し・読み込み） | 失うのは解決数・最高連続・事件簿の統計で、遊ぶことはできる。iOS アプリは iCloud バックアップや機種変更の移行で記録が移る。サポートページにも「機能は無い」と正直に書いてある |
| 初めて遊ぶ人への案内（遊び方・★1 練習への誘導） | ホームの一文、事件画面のルールの要約、判子の文字、提出ボタンの「あと〇人」、2段のヒントで先へ進める。★1 の練習ボタンは最初の画面に見えている。審査でも求められない |
| iOS アプリで文字を大きくする手段 | 遊びの中心の証言は16px（混んだ盤面でも15px）。小さいのは名札・仕事名・バッジなどの補助の文字。iPhone の「拡大表示」「ズーム機能」はアプリにも効く |
| 記録を消えにくくする（永続保存の要求・ホーム画面に追加の案内・manifest の screenshots） | iOS アプリは二重保存（localStorage と Preferences）済み。Safari が消すのは7日以上開かなかったときで、毎日遊ぶ人には当たらない。案内はサポートページの FAQ にある |
| 開いたままのホーム画面アプリ（PWA）に新しい版が届かない | 開き直せば届く（ページはネット優先）。iOS アプリと Artifact は対象外。版が上がっても失うのは解きかけの1問の途中だけ。戻ったときに自動で読み込み直すと、画面の履歴や結果が消える副作用もある |
| iOS アプリで毎朝の通知に気づく導線 | 許可は、利用者が設定でスイッチを入れたときだけ求める作り（Apple の推奨どおり）。審査メモに通知の場所を書いてある。結果画面で勧めるのは、続けて遊んでもらうための今後の候補 |
| `support.html` の「iOS アプリ版は準備中です」の書き換え | まだ申請していないので、今の文は正しい。承認されたら直す |
| Mac（Apple シリコン）・Vision Pro での配信の扱いを手順書に書く | 既定の ON のままでも申請は最後まで進み、リジェクトの理由にもならない。ネイティブ機能は使えない端末でも止まらない作り |
| iOS アプリに書体を同梱して、Google Fonts への通信をなくす | 書体が読めなくても端末の書体で全部動く（機内モードで確認済み）。通信はプライバシーポリシー・引き渡し手順・審査メモに書いてある |
| CI で `check-engine` を push のたびに回す | 決まりで、エンジンを変えたら手元で実行して docs に書いている。Pages はブランチから公開するので、CI が赤くなるのは公開のあと。止めるには Pages を Actions からのデプロイに作り替える必要がある。共有のランナーでは時間の項目が揺れる |
