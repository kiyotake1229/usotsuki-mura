## 仕様

### 1. 遊びのルール

- 村人は N 人（エンジンは3〜6人。日替わりは4〜6人）。全員が「正直者（H）」か「嘘つき（L）」のどちらか
- 正直者も嘘つきも最低1人ずついる（全員同じ側の問題は作らない）
- 犯人はちょうど1人。犯人が正直者のこともある
- 各村人がちょうど1つ証言する。正直者の証言は本当、嘘つきの証言はウソ
- 「村長のメモ」（確かな手がかり）が付くことがある。「Xは正直者だ」か「Xは嘘つきだ」の形で、必ず本当
- 答えはちょうど1つ。しかもエンジンの解き方（下の4章）で最後まで解ける問題だけを出す

### 2. 証言の種類

話し手を s、正直者かどうかを h[]、犯人を c とする。言い回しの本体は種類ごとに1〜3通りあり、同じ確率で選ぶ（表の「／」の左右）。

| 種類（type） | 本当になる条件 | 言い回しの本体 | 使える★ |
|---|---|---|---|
| `LIAR(x)` x≠s | x が嘘つき | 「{x}は嘘つき」 | ★1〜 |
| `HONEST(x)` x≠s | x が正直者 | 「{x}は正直者」 | ★1〜 |
| `CULPRIT(x)` | 犯人が x | 「犯人は{x}」／「やったのは{x}」／「{x}が犯人」。x=s なら「犯人はわたし」／「やったのはわたし」 | ★1〜 |
| `NOTCULPRIT(x)` | 犯人が x ではない | 「{x}は犯人じゃない」／「{x}はやってない」。x=s なら「わたしは犯人じゃない」／「わたしはやってない」 | ★1〜 |
| `CULPRIT_LIAR` | 犯人が嘘つき | 「犯人は嘘つき」／「やったのは嘘つき」 | ★2〜 |
| `CULPRIT_HONEST` | 犯人が正直者 | 「犯人は正直者」／「やったのは正直者」 | ★2〜 |
| `SAME(x,y)` | x と y が同じ側 | 「{x}と{y}は同じ側」／「{x}と{y}は、2人とも正直者か、2人とも嘘つき」。s を含むと「わたしと{y}は…」 | ★1〜（s を含む形は★2〜） |
| `DIFF(x,y)` | x と y が違う側 | 「{x}と{y}は違う側」／「{x}と{y}は、片方が正直者で片方が嘘つき」。s を含むと「わたしと{y}は…」 | 同上 |
| `CULPRIT_IN(x,y)` | 犯人が x か y | 「犯人は{x}か{y}のどちらか」／「{x}か{y}、どちらかが犯人」。s を含むと「わたしか{y}…」 | ★2〜 |
| `ATLEAST1LIAR(x,y)` x,y≠s | x と y の少なくとも1人が嘘つき | 「{x}と{y}のうち、少なくとも1人は嘘つき」／「{x}と{y}が2人とも正直者ってことはない」 | ★3 |
| `HONESTCOUNT(k)` 1≤k≤N−1 | 話し手を含む全員のうち正直者がちょうど k 人 | 「わたしたち{N}人のうち、正直者はちょうど{k}人」／「わたしも入れて数えると、正直者はちょうど{k}人」 | ★3 |

決まりごと:

- 自分について「わたしは正直者だ／嘘つきだ」は作らない
- 「わたしとXは同じ側／違う側」（話し手が何者でも X だけが決まる形）は1問に1つまで。`HONESTCOUNT` も1問に1つまで
- 語尾は村人ごとに決まった話し方（`style`）で付け、意味は変えない。です・ます調は使わない

| 話し方 | 名詞で終わる本体の語尾（N） | 「〜ない」で終わる本体の語尾（V） |
|---|---|---|
| `da` | だ | （付けない） |
| `dayo` | だよ | よ |
| `sa` | さ | さ |
| `daze` | だぜ | ぜ |
| `yo` | よ | わ |
| `nda` | なんだ | んだ |
| `zo` | だぞ | ぞ |
| `noyo` | なのよ | のよ |

- 証言の文は `text`（文字列）と `parts`（文字列と `{p: 人の番号}` の並び）の両方で持つ。画面は `parts` を使って人名を色付きのボタンにする

#### 4-2. Puzzle の形（JSON にできる素のオブジェクト）

2026-10-08 の日替わり（No.8）を縮めた例:

```js
{
  v: 2, seed: 2384941920, people: 5, star: 2, targetStar: 2,
  story: { title: '時計台の針が1時間進んだ', text: '村の時計台の針が、ひと晩で1時間進められていた。容疑者は5人。犯人は1人だけ。', job: null },
  villagers: [ { name: 'ハル', job: '農家', avatar: 11, color: 5 }, { name: 'スズ', job: '宿屋', avatar: 9, color: 0 }, /* …5人 */ ],
  given: { person: 1, value: 'H', text: '村長のメモ：スズは正直者だ', parts: ['村長のメモ：', {p:1}, 'は正直者だ'] },  // 無ければ null
  statements: [  // 1人1つ。speaker はカード順の番号（= statements の番号）
    { speaker: 3, type: 'SAME', a: 2, b: 4, k: null,
      text: 'シノとリツは、2人とも正直者か、2人とも嘘つきさ',
      parts: [{p:2}, 'と', {p:4}, 'は、2人とも正直者か、2人とも嘘つきさ'], refs: [2, 4] },
    /* … */ ],
  solution: { status: ['L','H','L','H','L'], culprit: 3 },
  steps: [ /* 解説の手順。下記 */ ],
  stats: { hyps: 1, chain: 3, sum: 3, back: 0, used: 5, unused: [] },  // unused = 解説に使われない証言の番号
  no: 8, date: '2026-10-08', weekday: 4   // 日替わりだけ
}
```

手順（`steps` の1つ）の形:

- 直接の手順: `{ kind:'direct', source: 'given' | 証言の番号, cat: 'G'|'A'|'B'|'C', text, facts }`
- 仮定の手順: `{ kind:'hypo', assume: {kind:'status', person, value:'H'|'L'} | {kind:'culprit', person}, text, sub: [直接の手順...], contradiction, contraSource: 食い違った証言の番号, conclusion, chain, facts }`
- `facts` は、その手順で新しく決まったこと。`{kind:'status', person, value}` か `{kind:'culprit', cand:[残った犯人候補]}`

#### 4-3. 全世界の表（速さのしくみ）

- 「世界」＝（正直者の組み合わせ h、犯人 c）。全部で 2^N × N 通り（6人で384通り）
- `ctxFor(N)` が人数ごとに1回だけ、あり得るすべての証言について「本当になる世界」をビットの表 `T` にする。犯人ごとに、h の 2^N 通りを 32bit の語で持つ（5人以下は1語、6人は2語）
- `consOf(証言, 話し手)` は「話し手が正直者なら本当、嘘つきならウソ」になる世界の集合
- 解の数は、全員の `consOf` と村長のメモの集合をビットの AND で重ね、残ったビットを数える（`countSolutions`）
- この持ち方のため、7人以上には対応していない（#0003 で語の数を増やす形に改め、9人まで対応した）

#### 4-4. 解き方（人の考え方をまねる）

分かっていること（事実）は、各人の状態 `st[i]`（0=不明・1=正直者・2=嘘つき）と犯人候補の集合 `cand`。村長のメモがあれば、最初の手順「村長のメモは必ず本当。→ スズは正直者」で事実にする。

**直接の推論（`scan` / `evalC`）**

1つの証言と、いまの事実だけを使う。事実と合い、かつ「話し手が正直者 ⇔ 証言が本当」を満たす世界の集合 W を作る。W 全体で正直者か嘘つきかが1つに決まる人、W に残る犯人候補が、新しい事実になる。W が空なら矛盾。何も新しく決まらない証言は飛ばす。

使える手が複数あるときの優先順（各グループの中ではカードの並び順で最初のもの）:

| 順 | 区分 | 内容 |
|---|---|---|
| 1 | A | 話し手の正直/嘘つきがもう分かっている証言 |
| 2 | B | 話し手は不明だが、証言の中身の本当/ウソが事実だけで決まり、そこから話し手が分かる（逆向きの推理。`truthDet`） |
| 3 | C | 話し手も中身も不明だが、話し手が正直者でも嘘つきでも同じことが決まる（1つの証言の中での場合分け） |
| 4 | Wk | A のうち「犯人は嘘つき／正直者だ」で犯人候補を一部しぼるだけのもの（後回し） |

使わない手:

- 話し手が未確定の「犯人は嘘つきだ」を場合分けして「話し手は犯人ではない」とだけ決める手（自己言及のひっかけ）。必要なときは仮定「もし犯人が〇〇だとすると」で扱い、矛盾の文は「犯人が〇〇なら、〇〇の『犯人は嘘つきだ』は『わたしは嘘つきだ』と言っているのと同じ」の形にする
- 仮定の中での C（場合分けは実質もう一段の仮定になるため）

**仮定の推論（`findHypo` / `tryHypo`）**

直接の推論で進めなくなったら、未確定の項目を1つ仮に決め、直接の推論（C を除く）だけを続けて矛盾が出るか試す。

1. まず人の仮定。不明な人をカード順に、「正直者だとすると」「嘘つきだとすると」の順で試す
2. 連鎖の長さ＝中の手の数＋矛盾の1手（上限10）。最も短いものを選ぶ。同じ長さなら先に見つけたもの（カード順・正直者→嘘つき）
3. 人の仮定が1つも成り立たないときだけ、犯人の仮定（「もし犯人が〇〇だとすると」）を候補ごとに試す
4. 矛盾が出たら、仮定の逆が新しい事実（人なら逆の側、犯人ならその人を候補から外す）
5. 仮定の中で別の仮定は置かない（入れ子なし）

全員の正直/嘘つきと犯人1人が決まるまで、直接 → 仮定 をくり返す（`solveCore`）。仮定でも進めないパズルは不採用。

#### 4-5. ★の決め方

- `hyps` = 仮定の手順の数、`chain` = 仮定の連鎖の最長、`sum` = 仮定の長さの合計、`back` = 区分 B の手の数

| ★ | 条件（`starOf`） | 練習画面での説明 |
|---|---|---|
| ★1 | hyps = 0（村長のメモを入口に順にたどれる） | やさしい: 村長のメモから順にたどる |
| ★2 | hyps = 1 かつ chain ≤ 4 | ふつう: 1回だけ仮定して確かめる |
| ★3 | hyps ≥ 2 または chain ≥ 5 | むずかしい: 仮定を重ねてじっくり |

表示する★は実測値。生成は目標の★に合うまでやり直す。

**同じ★の中の幅（band、`BANDS`）**

| 名前 | 使う場所 | 条件 |
|---|---|---|
| `star3` | ★3 の練習（既定） | hyps ≤ 3 かつ（sum ≥ 5 または chain ≥ 5）。「仮定2回・各2手」のやさしすぎる★3と、仮定4回以上の重すぎる★3を外す |
| `mon` | 月 ★1・4人 | なし |
| `tue` | 火 ★1・5人 | back ≥ 3（逆向きの推理が3回以上） |
| `wed` | 水 ★2・4人 | chain ≤ 3、かつ村長のメモあり（メモは必ず付ける） |
| `thu` | 木 ★2・5人 | chain = 3 |
| `fri` | 金 ★2・6人 | chain ≥ 3（★2 なので実際は3〜4） |
| `sat` | 土 ★3・5人 | hyps = 2 かつ sum が5〜6 |
| `sun` | 日 ★3・6人 | hyps ≤ 3 かつ（chain ≥ 5 または sum ≥ 7） |

★1・★2 の練習には band を付けない。

#### 4-6. 問題の作り方（`buildCore` / `buildCandidate`）

1. 乱数は `hash32(seed + '|' + 人数 + '|' + ★)` を種にした mulberry32 だけ。生成の中で `Math.random` は使わない
2. 村長のメモを付けるか: ★1 は必ず、★2 は 75%、★3 は 35%（`GIVEN_RATE`。入口の形を散らすため）。水曜（`wed`）は必ず付ける。★2・★3 で 900 回目（上限の 60%）まで合格が出なければ、付ける／付けないを入れ替えて探す
3. 候補を1つ作る（`buildCandidate`）
   1. 先に正解を決める。正直者の組み合わせ h（全員同じ側は除く）、犯人 c、メモの対象者（メモの値は正解どおり）
   2. 1人ずつ、その人の正直/嘘つきと本当/ウソが合う証言を選ぶ。まず★ごとの重み（下表）で種類を選び、その種類の中から等確率で選ぶ。同じ証言の重複、`HONESTCOUNT` 2つ、「わたしとX」2つは避ける
   3. 解の数が1つになるまで、最大50回、ランダムな1人の証言を差し替える（山登り）。90% の確率で「残っている別解の世界を1つ否定する」証言に限る。解の数が減れば採用、同じなら半々で採用
   4. 50回で1つにならなければ捨てる
4. 解いてみる（`solveCore`）。最後まで解けなければ捨てる
5. 合格: 実測★＝目標★、band に入る、解説に使われない証言が0個（600 回目からは1個まで）。合格したらそこで終わる
6. 上限 1,500 回で合格が無ければ、点数（★の差×100＋band 外なら50＋未使用の数×10＋未使用2個以上なら1000）が最小のものを使う。1問も解けなければ例外 `generate failed`

★ごとの種類の重み（`WEIGHTS`）:

| 種類 | ★1 | ★2 | ★3 |
|---|---|---|---|
| LIAR | 4 | 3 | 2.5 |
| HONEST | 3 | 2 | 1.5 |
| CULPRIT | 2 | 1.5 | 1 |
| NOTCULPRIT | 2 | 1.5 | 1 |
| CULPRIT_LIAR | — | 1.2 | 1 |
| CULPRIT_HONEST | — | 1.2 | 1 |
| SAME | 1 | 1.2 | 1 |
| DIFF | 1 | 1.2 | 1 |
| CULPRIT_IN | — | 1.5 | 1.2 |
| ATLEAST1LIAR | — | — | 1.5 |
| HONESTCOUNT | — | — | 1 |

論理の部分ができたら、見た目を付ける（`assemble`）。顔ぶれ（店の主人を除いた16人から N 人）、色（0〜7 の並べ替え）、言い回しを選び、解説文と `stats` を作る。

- 練習（`generate`）: 見た目の乱数は `hash32('dress|' + seed + '|' + 人数 + '|' + ★)`。事件は通年の35件から選ぶ
- 日替わり（`daily`）: 下の 4-7

**品質フィルタのまとめ**: 解が1つ（総当たり）／エンジンで最後まで解ける／解説に使われない証言は最大1つ（できれば0）／嘘つきは1〜N−1人／目標の★と band に合う（無理なら最も近いもの）。

#### 4-7. 日替わり（`dailyConfig` / `daily`）

- 事件番号 No. ＝ 2026-10-01 を No.1 とした通し番号。日付の文字列から計算するので、時差の影響は受けない。「今日」は画面側が `Engine.localDateStr()`（端末のローカル日付）で決める
- seed ＝ `hash32('usotsuki-YYYYMMDD')`
- 曜日で人数・★・band が決まる（`WEEK`）

| 曜日 | 月 | 火 | 水 | 木 | 金 | 土 | 日 |
|---|---|---|---|---|---|---|---|
| ★ | 1 | 1 | 2 | 2 | 2 | 3 | 3 |
| 人数 | 4 | 5 | 4 | 5 | 6 | 5 | 6 |
| band | mon | tue | wed | thu | fri | sat | sun |

- 事件の割り当て（`storyIndexForNo`）は生成の乱数とは別。No.1 から1日ずつ順に決めて覚えておく
  - その日の月に出てよい事件（通年＋季節が合うもの）を、最後に出た日が古い順に並べる。直前の6日に出た事件と店の主人 `job` か題材 `g` が同じものは外し（残りが3件未満なら外さない）、先頭3件から `hash32('usotsuki-story-' + No.) % 3` で1件選ぶ。同じ事件はおよそ1か月、同じ店・同じ題材の事件は7日以上あく（羊・時計・帽子などが同じ週に並ばない）
  - 新しく出せるようになった事件（No.1 の日や季節の始まり）は、最後に出た日を直前の期間に散らしておく（`hash32('usotsuki-story-off-' + 事件の番号)`）。季節の頭にかたまらないようにするため
  - No.0 以前の日付は計算はできる（通年の事件から hash で選ぶ）が、事件簿には出さない
- 顔ぶれは `hash32('usotsuki-cast-YYYYMMDD')` の乱数で選ぶ。事件の店の主人は入れない
- 論理の部分は `buildCore(seed, 人数, ★, band)`

#### 4-8. 解説文（`makeWriter`）

| 手順 | 文の形（実際の出力） |
|---|---|
| 村長のメモ | 村長のメモは必ず本当。→ スズは正直者 |
| A（話し手が既知） | スズは正直者なので、『カイは正直者だよ』は本当。→ カイは正直者 |
| A（補足つき） | カイは正直者なので、『シノとリツは、2人とも正直者か、2人とも嘘つきさ』は本当。リツは嘘つきなので → シノは嘘つき |
| A（犯人の絞り込み） | リツは嘘つきなので、『わたしかスズ、どちらかが犯人だ』はウソ。→ スズとリツは犯人ではない。犯人はハル・シノ・カイのだれか |
| B（逆向き） | イツキは正直者なので、エマの『イツキは正直者なんだ』は本当。→ エマは正直者（だれの証言かを先に書く） |
| C（わたしとX） | ハルは『わたしとサクは同じ側なんだ』と言っている。ハルが正直者なら本当なので、サクも正直者。ハルが嘘つきならウソなので、サクはハルと違う側、つまり正直者。どちらにしても → サクは正直者 |
| C（長い場合分け） | 「〇〇が正直者か嘘つきかで分けて考える。」のあと改行して「・正直者なら…」「・嘘つきなら…」「どちらにしても → …」 |
| 仮定 | もしハルが正直者だとすると……（中の手を字下げで並べる）／ところが、シノは正直者なので『犯人は嘘つきよ』は本当のはず。でも全員が正直者で、犯人も正直者なので、ウソになってしまう。／だから、ハルは嘘つき |
| 犯人の仮定 | もし犯人がシノだとすると……／ところが、犯人がシノなら、シノの『犯人は嘘つきよ』は「わたしは嘘つきだ」と言っているのと同じ。正直者ならウソに、嘘つきなら本当になってしまうので、だれにも言えない。／だから、シノは犯人ではない |

文の決まり:

- 結論は「→」の後ろ。画面はここを太字にする
- 「つまり、〜」は結論と同じ名前をくり返さない（例「つまり、2人とも正直者。」）
- 人数の説明は、だれを数えたかを書く（「正直者はもうアオイとウタの2人がそろったので」「スズが嘘つきだと、正直者はモモ1人だけになってしまうので」）
- 犯人の絞り込みは「→ 犯人はアオイかエマ」「→ 犯人はカイではない」「→ 犯人はアオイ」など
- 「〜とわかっているので」「すると、この証言は」「みな」は使わない。`undefined` / `NaN` / `null` / `[object` は絶対に出さない（テストで確認）

#### 4-9. 答え合わせ（`check`）

1. 全員の判定と犯人がそろっていなければ `{ok:false, contradiction:null, incomplete:true, message:'全員の判定と犯人を選んでから提出してね。'}`
2. 村長のメモと合わなければ最優先で `kind:'given'`（例「あなたの推理では、スズは嘘つき。でも村長のメモには「スズは正直者だ」とある。」）
3. 次にカード順で、最初に食い違う証言を `kind:'statement'`（`index` と `speaker` 付き）で返す
   - 例「あなたの推理では、イツキは正直者。でもその場合、ウタは嘘つきなので、イツキの『ウタは正直者だ』はウソになってしまう。」
   - 犯人についての証言（CULPRIT / NOTCULPRIT / CULPRIT_IN / CULPRIT_LIAR / CULPRIT_HONEST）は選んだ犯人も書く。例「あなたの推理では、リツは嘘つきで、犯人はスズ。でもその場合、犯人はスズなので、リツの『わたしかスズ、どちらかが犯人だ』は本当になってしまう。」
4. 食い違いが無く正解と同じなら `{ok:true}`。食い違いが無いのに正解と違う場合（解が1つなので理屈の上では起きない）は「どの証言とも食い違いは見つからないけれど、答えとは違うよ。」

#### 4-10. ヒント（`hint`）

- 範囲外・整数でない `culprit` は「未選択」、`'H'`/`'L'` 以外の印は「未判定」として扱う。`focus` には必ず実在する人の番号だけを入れる
- 解説の手順を先頭から見ていき、次のどれかで止まる
  - その手順で決まる項目にプレイヤーの印が付いていて間違っている → 見直し（`kind:'review'`。「〇〇の判定を見直してみよう。」／「犯人の選び方を見直してみよう。」）
  - その手順で決まる項目にまだ印が無い → この手順を答える
  - 最後まで印がそろっている → `kind:'done'`（「全員の判定と犯人がそろいました。「推理を提出」を押してみよう。」）
- 犯人候補をしぼるだけの手順（犯人がまだ1人に決まらない）は画面で印を付けられないので、それだけでは「未確定」とみなさない。後の手順の印がそろっていれば済んだものとみなす。`seen` に入っている手順も済んだものとみなす。まだ済んでいない絞り込みは、次に印の付く手順とひとまとめにして返す（`steps` に全部の番号）
- 1段目（level 1）は考える場所だけ。答えは言わない
  - メモ: 「まずは村長のメモを見てみよう。メモは必ず本当だよ。」
  - A: 「スズは正直者とわかったね。スズの証言から何がわかるか考えてみよう。」（話し手は前の手順で決まり、プレイヤーも正しく印を付けている人だけ）
  - B: 「〇〇の証言は、わかっていることから本当かウソか決められるよ。」
  - C: 「〇〇が正直者の場合と嘘つきの場合を、両方考えてみよう。」
  - 人の仮定: 「ハルを正直者か嘘つきのどちらかに仮に決めて、食い違いが出ないか確かめてみよう。」（どちらを仮定するかは言わない）
  - 犯人の仮定: 「犯人の候補を1人ずつ仮に決めて、〇〇の証言と食い違わないか確かめてみよう。」
- 2段目（level 2）は次の手順の解説文そのもの。まとめた手順は改行でつなぐ（仮定は見出し・字下げの中身・矛盾・結論）

#### 4-11. 再現性を守るしくみ

- 乱数は seed から決まる mulberry32 だけ。同じ seed・設定なら同じ問題（JSON で完全一致）
- 表（`POOL` / `ENDINGS` / `STORIES` / `TPL` / `WEIGHTS` / `BANDS` / `WEEK`）は深く凍結し、`Engine` と `_internal` も凍結。外から生成のパラメータは変えられない
- 論理の部分（`coreCache`）と完成した問題（`pzCache`）をそれぞれ最大41件まで覚える。`generate` / `daily` は JSON の深いコピーを返すので、受け取った側が書き換えても覚えた問題は変わらない

### 5. 画面（APP）

画面は6つ。HTML は `<section class="view" id="v-...">` で、関数 `show(名前)` が切り替える。画面の行き来は `go(名前)` / `goBack()` がブラウザの履歴にも積む（`history.pushState`。`navStack` に通ってきた画面を覚える）。Android の戻るボタン・iOS の戻るスワイプでアプリ内の前の画面に戻り、結果や下のパネルが開いていれば先にそれを閉じる。すでに通ってきた画面へ行くときは、そこまで履歴も戻す（例: 解説→［ホームへ］で履歴も最初に戻る）。重ねて出すものは `#playBar`（事件画面の下部固定バー）、`#sheet`（下から出るパネル。ヒントと食い違い）、`#result`（結果）、`#toast`（短いお知らせ）。

**ホーム（`#v-home`、`renderHome`）**

- 夜明けの村のイラスト（SVG。ダークでは夜の村と灯台の光）、見出し「嘘つき村の事件簿」
- 今日の事件カード（`#todayCard`）: No.・日付（曜日）・★・容疑者の人数・題名（`dailyConfig` だけで出す）・状態。表示したまま日付が変わったら描き直す（0.5秒ごとの確認）。作り方の版が違う途中の記録は「未解決」として見せる（`liveRec`）

- 練習: ★1「やさしい」・★2「ふつう」・★3「むずかしい」。途中は★ごとに1件ずつ残り、判定・犯人・ヒント・ミスのどれかに手を付けたものだけ「途中」の印（`touched`）。開いただけのものは印を付けないが、もう一度開くと同じ問題
- 事件簿・遊び方・設定への入口、「通信はしません。記録はこの端末の中だけに保存されます。」

**事件（`#v-play`、`openCase` → `startCase` → `renderBoard`）**

- 上部（`.topbar`）: 戻る（ひとつ前の画面へ。事件簿から開いたときは事件簿、遊び方の［練習（★1）で試す］から開いたときは遊び方）、No.（練習は「練習」）と★、経過時間、ミス数
- 開くとき「事件ファイルを用意しています」を先に描き、次のフレームで問題を作る（最低0.38秒見せる）。作れなければ「もう一度開く」
- あらまし（題名・本文。「あらましをたたむ／読む」で折りたたみ）、ルールの要約（正直者／嘘つき、同じ側／違う側。`HONESTCOUNT` があれば「話した本人も入れた全員で数える」）
- 村長のメモ（`#memo`、「確かな手がかり」と村長の角印）
- 村人カード（`.vcard#card-番号`）を縦に並べる: 似顔絵、名前と仕事、吹き出しの証言（人名は色付きのボタンで、押すとその人のカードへ移動して光る）、その問題で初めて出る「同じ側」「違う側」の下に意味を小さく添える、判子ボタン［正直者］［嘘つき］（もう一度押すと解除）・［犯人］（1人だけ）

- 下部固定バー: ［ヒント］と［推理を提出］。そろうまで押せず「あと〇人・犯人も選ぶ」「犯人を1人選ぶ」などと出る

- ヒント: 1段目をパネルで出し、「もっと詳しく（次の一手）」で2段目。2段目は解説と同じ形（仮定は字下げの箱）。関係するカードを光らせる。回数は「段｜次に印が付く手順」の組（`hintSeen`。保存する）が初めてのときだけ増やす。2段目を見たあとの同じ手順の1段目、閉じて開き直した同じヒント、リロード後の同じヒントは数えない。見直しのヒントは文ごとに1回。全部そろった案内（done）は数えない
- 練習の［次の事件］は、直前の練習と同じ題名になったら seed を変えて作り直す（最大4回）
- 犯人候補の絞り込みの手順は、2段目で見せたとき、または1段目で見せたあと印を付けたときに `seen` として覚え、次から飛ばしてもらう

**解説（`#v-explain`、`renderExplain`）**

### 6. データの保存

- 保存先は `localStorage` のキー **`usotsuki.v1`** 1つ。全体を JSON で保存（`persist`）。読み書きはすべて try/catch で、保存できない環境でも遊べる
- 読むとき（`readStore` → `sanitize`）は項目ごとに型を確かめて初期値に合成する。数は有限の数か数字だけの文字列だけ（だめなら0）、`attempts` は □■ だけ、`settings` は boolean と 'auto'|'light'|'dark' だけ、日付のキーは YYYY-MM-DD だけ。`v` が 1 でなければ読み捨てて初期値。壊れた値で NaN や文字のつながりは出ない
- 記録を変えるときは必ず `update(関数)` を通す。保存済みの最新を読み直してから自分の変更だけを重ねて書くので、別のタブや PWA で同時に開いていても、ほかで付けた解決・連続日数を上書きしない。解決済みの日の記録は上書きしない。別のタブで先に解いていた日を解いたときは二重に数えず、その記録を見せる。`storage` イベントでほかのタブの変更を読み直し、ホーム・事件簿・設定を描き直す

```js
{ v: 1,
  settings: { sound: true, haptics: true, theme: 'auto' },          // theme: 'auto' | 'light' | 'dark'
  daily: { 'YYYY-MM-DD': { state: 'playing'|'solved', marks: ['H','L',null,...], culprit: 番号|null,
                           mistakes, hints, attempts: '□□■', elapsed: 秒, solvedOnDay: bool,
                           openedOnDay: true（その日のうちに開いたときだけ。#0010）,
                           hintSeen: ['1|s6', ...], seenSteps: [手順の番号...], lastWrong: 'HL-H|3'|null,
                           streak: 解いた時点の連続日数（その日のうちに解いたときだけ）,
                           title: '事件名', v: Engine.VERSION } },
  practice: { byStar: { 1: 途中|null, 2: 途中|null, 3: 途中|null },   // 途中 = { seed, star, people, marks, culprit, mistakes,
              solved: 練習で解いた数 },                              //          hints, attempts, elapsed, hintSeen, seenSteps, lastWrong, v }
  stats: { streak, bestStreak, lastDailyDate: 'YYYY-MM-DD'|null, totalSolved, perfect } }
```

- 連続日数: 日替わりをその日のうちに解いたときだけ数える。最後に解いた日が昨日なら +1、そうでなければ 1。表示では、最後に解いた日が昨日より前なら 0
  - （#0010 で追記）その日のうちに開いた事件は、0時をまたいでも**翌朝3時までに解けば**開いた日の分として数える。数える基準は「今日」ではなく事件の日付
    - 「その日のうちに開いた」は日替わりの記録（`openedOnDay: true`）に残すので、ホームに戻ってから開き直したとき・読み込み直したとき・アプリが落ちて開き直したときも同じに数える
    - 0〜3時のあいだ、前の日に開いた事件がまだ解けていなければ、ホームに「昨日の事件 No.X は捜査の途中です／3時までに解けば、連続日数に数えます」（押すとその事件を開く）を出し、ホームと事件簿の連続も切れていない扱いにする
    - 事件の画面で日付が変わると「日付が変わりました。3時までに解けば、連続日数に数えます」、3時を過ぎると（端末を3時過ぎに起こしたときも）「翌朝3時を過ぎたので、この事件は連続日数に数えません」と出る。3時を過ぎて解いた結果は「翌朝3時を過ぎてから解いた事件は、連続日数に数えません」
  - （#0010 で追記）端末の日付が最後に解いた日より前に戻ったときは、**2日以内（時差で起こる幅）なら**連続をそのまま見せ、解いても連続と最後に解いた日を巻き戻さない。それより大きく離れていたら時計のずれとみなし、表示は0、解いたらその日から1日目として数え直す（先の日付で解いたあと時計を戻しても、連続が止まったままにならない。最高連続は残る）
  - （#0010 で追記）端末の日付が No.1（2026-10-01）より前なら、画面は「今日」を No.1 の日として扱う
- `totalSolved` と `perfect`（ミス0。ヒントは使ってもよい）は日替わりだけを数える。練習は `practice.solved`
- 練習の途中は★ごとに1件ずつ（`practice.byStar`）。同じ★のボタンなら続きから、解くとその★の分だけ消える。古い形（`practice.current` 1件）は読み込むときに `byStar` へ移す
- 版の確認: 途中の記録の `v` が `Engine.VERSION` と違えば、別の問題のものなので判定・犯人・ミス・ヒント・時間・提出の記録・見たヒントをすべて使わず、最初から始める。解決済みはそのまま「解決」
- 解決済みの日を開くと、盤面は正解で固定して見せる

### 7. 通信と外部リソース・音・見た目

- 外部へデータを送る処理は無い（`fetch` / `XMLHttpRequest` / `sendBeacon` / `WebSocket` は使っていない）
- 外から読むのは Google Fonts だけ: Shippori Mincho B1（600・800。見出し・事件名）、Zen Kaku Gothic New（400・500・700。本文）。`<head>` の小さなスクリプトが `media="print"` で読み始め、読み終わったら `all` に切り替えるので、回線が遅くても表示を止めない（JavaScript が無いときは `<noscript>` の通常の読み込み）。読めなくても CSS 変数 `--f-display` / `--f-body` に並べた端末の文字で表示される
- CDN のスクリプト・画像ファイル・音声ファイルは使っていない。アイコンは HTML 内の SVG（`<symbol id="i-...">`）、似顔絵は `avatarSVG(番号, 色)` が描く SVG（顔＋髪型＋仕事の小物）、判子は `sealSVG('H'|'L'|'C')` など
- 効果音は WebAudio でその場で作る（`SFX`: 判子 `stamp`・解除 `clear`・不正解 `wrong`・ヒント `hint`・解決 `solve`）。最初に画面に触れたときに AudioContext を作る。設定で OFF にできる
- 振動は `navigator.vibrate` があるときだけ（判子 8ms、不正解 30-40-30ms、解決 20-60-40ms）
- 配色は `:root` の CSS 変数（判子の上の白 `--on-shu`、月 `--moon`、星 `--star-dot`、スイッチのつまみ `--knob-on` / `--knob-off` / `--knob-ring` / `--knob-shadow` も含め、色はすべて変数を通す。似顔絵の SVG の中の色だけは絵の一部として直接書いている）。ライト＝夜明けの紙面（青みのある白〜薄藍、藍のインク、朱の判子）、ダーク＝夜の村（深い藍）。`@media (prefers-color-scheme: dark)` の `:root:not([data-theme="light"])` と `:root[data-theme="dark"]` で上書き。テーマ切替は `<html data-theme>` を付け外しし、`theme-color` も合わせる
- 幅: 中央 480px の1列、左右16px。370px 以下で詰める。上部と下部固定バーは safe-area を考慮。横スクロールなし
- 改行: 説明文・吹き出し・解説・パネルは `word-break:auto-phrase`（日本語の文節で折り返す。Chrome 系）と `text-wrap:pretty`。ホームの説明文と練習カードは `<wbr>` を入れ、`auto-phrase` の無いブラウザでは `word-break:keep-all` で同じ位置で折り返す
- ボタンは `touch-action:manipulation`（ダブルタップでの拡大を待たない）
- 動き: カードの順番表示、判子を押す動き、間違い時の揺れ、解決の大きな判子。`prefers-reduced-motion` では控える

   - ところが、アオイは正直者なので『犯人はエマだよ』は本当のはず。でもエマは犯人ではないので、ウソになってしまう。

### 11. 既知の制限・注意点

- 7人以上の問題は作れない（全世界の表が64bitまでの持ち方）。9人の問題には表の作り直しと速さの確認が要る（→ #0003 で解消）
- 問題の作り方（エンジンの手順・表・定数・事件や村人の追加）を変えると、全員の日替わり問題が変わる。`VERSION` を上げ、docs に書く。解決済みの日は「解決」のまま残るが、盤面に出るのは新しい作り方の問題になる
- 「通信なし」の表記: 起動時に Google Fonts を読みに行く。完全オフラインや App Store の「データを収集しません」を説明するときはこの点に触れる
- PWA ではないので、通信の無い所で開き直せる保証は無い（Service Worker もホーム画面用の設定も無い）（→ #0005 で解消）
- 振動は `navigator.vibrate` だけ。iPhone の Safari には無いので、Web 版の iPhone では振動しない（iOS アプリ化で触覚フィードバックに置き換える予定）
- 日替わりは開いただけで「途中」になる（時間が進み始めるため）。練習は手を付けるまで「途中」の印を付けない
- 画面の履歴は、ページを読み込み直すと最初（ホーム）からになる。読み込み直す前の履歴が残っているときは、戻るを1回押しても見た目が変わらないことがある
- 日替わりは端末のローカル日付で決まる。時差のある端末同士では、同じ時刻でも別の問題になる
- データの書き出し・読み込みは無い
- 画面の操作確認は #0002 でローカル（Chrome 系のブラウザ、375px・360px・PC幅、ライト・ダーク）で行った。スマホ実機・Claude Artifact 上での確認はまだ
